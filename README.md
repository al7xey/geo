# GEO Audit

## Быстрый запуск интерфейса

Нужны Python 3.12+ и Node.js 24. Windows, macOS и Linux поддерживаются без WSL.

```console
python run.py setup
python run.py ui-setup
python run.py ui
```

Откройте http://127.0.0.1:8767. Без `--live` работают учебные ответы без расходов.
Для настоящего запуска создайте локальный `.env` по `.env.example`:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
ANTHROPIC_API_KEY=ваш_ключ_Claude
GEMINI_API_KEY=ваш_ключ_Gemini_или_Vertex
DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
GEO_OPENAI_MODEL=gpt-4o-mini
GEO_CLAUDE_MODEL=claude-haiku-4-5-20251001
GEO_GEMINI_MODEL=gemini-3.5-flash-lite
GEO_DEEPSEEK_MODEL=deepseek-v4-flash
```

Не добавляйте `.env` в Git и не используйте переменные `VITE_*` для ключей.
Для исходного шага 2 также положите свой файл правил в
`private/prompts/prompt_step2_profile_and_queries.md`. Он намеренно не публикуется.

```console
python run.py ui --live
```

Кнопка «Подготовить вопросы» запускает чтение сайта и создание профиля и вопросов
существующими шагами 0–2. Затем вы проверяете вопросы в интерфейсе шага 3 и
отдельно подтверждаете платный сбор ответов. Далее выполняются шаги 5–12.
Регистрация аккаунта не требуется: вход пока учебный.
Сбор: максимум 20 вопросов, один ответ на вопрос и систему, до 800 выходных
токенов. Перепроверка: до 20 запросов по 1600 токенов, материалы — ещё один.
При сбое платные запросы автоматически не повторяются; пропуски видны в отчёте.
Наличие ключа само по себе ничего не запускает.

[Все подключения, ограничения и устройство интерфейса](docs/FRONTEND.md).
Исходные программы шагов 0–4 сохранены; веб-режим сбора использует короткие
ответы без поиска и адаптивных повторов. Исходный сборщик с собственными
настройками по-прежнему запускается через `python run.py collect`.


Программа проверяет техническую доступность сайта и разбирает ответы нейросетей
о компании. Общая цепочка включает шаги **0–12**. Исходные ответы, цитаты,
результаты проверок и причины неопределённости сохраняются в файлах.

Шаги 0–4 перенесены из предоставленного архива без изменений исходного кода.
Шаги 5–8 подключены к их формату данных. Контрольные суммы 89 защищённых файлов
проверяются тестом по [списку исходников](docs/UPSTREAM_0_4_SHA256.json).

## Что работает сейчас

| Часть | Состояние |
| --- | --- |
| Шаги 0–1 | Безопасное подключение, обход разрешённых страниц, извлечение текста и технические проверки |
| Шаг 2 | Профиль компании и вопросы; настоящее выполнение требует API и личной инструкции |
| Шаг 3 | Локальная страница для проверки и утверждения вопросов человеком |
| Шаг 4 | Сбор ответов с ограничениями расходов и повторами; есть проверка плана без отправки запросов |
| Шаги 5–6 | Разбор сохранённых ответов и первичная разметка локальными правилами |
| Шаг 7 | Независимая выборка и приём файла внешней проверки; автоматическое обращение к модели отключено |
| Шаг 8 | Объединение названий, группировка источников и очередь неясных случаев |
| Шаги 9–12 | Локальные расчёты, темы для проверки, план действий и итоговый HTML-отчёт; модельная подготовка текста отключена |

После установки учебный запуск не требует ключей и интернета. Настоящие шаги
0–1 обращаются к выбранному сайту, шаги 2 и 4 — к внешним моделям.
Настоящие подключения к моделям в рамках проверки проекта не выполнялись:
адреса API, доступность моделей и права ключей нужно проверить отдельно.

Правила шагов 5–8 не заменяют полноценную смысловую проверку. Неясное название
или роль остаются неопределёнными. Добавление ключа само по себе не включает
модельных исполнителей шагов 6–8: их ещё нужно реализовать и проверить.

## Быстрый запуск без API

Нужен установленный Python 3.12 или новее. Поддерживаются Windows, macOS и Linux.
Ubuntu, WSL, Docker и права администратора не требуются.
Откройте терминал и перейдите в папку скачанного или клонированного проекта.

На Windows:

```powershell
python run.py setup
python run.py demo --through12
```

Если команда `python` отсутствует, используйте `py -3.12`.
На macOS и Linux:

```sh
python3 run.py setup
python3 run.py demo --through12
```

`setup` устанавливает закреплённые зависимости из `uv.lock` в `.venv`.
Служебный установщик uv 0.9.7 находится отдельно в `.bootstrap`.
Для первой установки нужен интернет; подходящий Python 3.12 при необходимости
может быть загружен установщиком. Системные пакеты Python не меняются.
Активировать окружение вручную и повторять установку перед каждым запуском не нужно.

`demo` обрабатывает **480 вымышленных ответов на 20 вопросов**, выполняет шаги
5–12 и проверяет сохранённую цепочку. Используются три учебные системы,
по восемь повторов на вопрос. Это проверка работы программы, а не измерение
популярности настоящей компании. Исходный набор:
[examples/mock_answers_v1](examples/mock_answers_v1).

Путь к `report.html` появится в терминале. Откройте файл самостоятельно:
браузер автоматически не запускается. Каждый запуск создаёт новую папку
`private/demo/ДАТА-ВРЕМЯ/`. Внутри находятся учебный вход, `result` шагов 5–8 и `final` с итоговым отчётом.
Отчёт содержит ссылки на результаты каждого шага.

В учебном преобразовании оборванные и другие непригодные ответы становятся
ошибками сбора. Они не считаются отрицательным мнением о компании.
Оригинальный учебный набор при этом не изменяется.

## Общий порядок работы

```text
Адрес сайта и настройки
  → 0: проверка подключения
  → 1: страницы, текст и технические проверки
  → 2: профиль компании и вопросы
  → 3: проверка вопросов человеком
  → 4: сбор ответов
  → 5: разбор текста, названий и ссылок
  → 6: первичная разметка присутствия и роли компании
  → 7: независимая выборочная проверка — пока без автоматического API
  → 8: объединение названий и группировка источников
  → 9: доли, разброс и устойчивость
  → 10: темы и задание подготовки содержания
  → 11: находки и план действий
  → 12: итоговый отчёт и контроль чисел
```

Сквозной учебный тест вызывает настоящие функции шагов 0–8, но подменяет
внешний сайт и ответы моделей управляемыми тестовыми данными. Это тест
`test_full_unchanged_zero_to_four_and_adapted_five_to_eight` в
[tests/test_step4_to_step8.py](tests/test_step4_to_step8.py).
Команда `demo` без флага показывает шаги 5–8; `demo --through12` завершает также расчёты, план и итоговый отчёт.

## Шаги: вход, действия и выход

### Шаг 0. Проверка адреса и подключения

**Вход:** адрес сайта и ограничения проверки.

**Действия:** приведение адреса к единому виду, проверка назначения подключения,
разрешённых переходов, сертификата TLS и фактического адреса соединения.
Учитываются попытки и время. Заблокированный или неподходящий сайт
не выдаётся за успешно проверенный.

**Выход:** `site.json`, `config.json`, `budget.json`, журнал и исходные данные
в `raw/`. `site.json` записывается последним как признак завершения шага.

### Шаг 1. Обход сайта и подготовка текста

**Вход:** проверенный результат шага 0, общий оставшийся бюджет и настройки обхода.

**Действия:** чтение `robots.txt`, карт сайта и разрешённых внутренних страниц;
извлечение текста; проверка директив индексации и технических признаков.
Определяется, хватает ли содержательного материала для следующего шага.
Описание компании от пользователя может дополнить материал, но не исправляет
технические ошибки сайта и не меняет результат проверки `robots.txt`.

**Выход:** отдельная папка с `crawl.json`, `checks.json`, `run.json`, исходными
текстами и сведениями об их происхождении. Шаг 0 не переписывается.
Корпус текста можно прочитать без повторного посещения сайта.

### Шаг 2. Профиль компании и вопросы

**Вход:** проверенные тексты шага 1, страна, сведения о компании и личная инструкция
`private/prompts/prompt_step2_profile_and_queries.md`.

**Действия:** составление профиля с вариантами названия, категорией и основаниями;
подготовка 40 вопросов — по 10 на каждый уровень. В исходном наборе 35 вопросов
не подсказывают название компании, ещё 5 содержат бренд и не входят в измерение
органической видимости. При недостатке текста можно явно передать описание.
`--no-web` отключает внешнюю поисковую справку, но не модель профиля и вопросов.

**Выход:** `private/step2_fast/PROJECT/`: `profile.json`, `prompts.json`,
`step2_report.json` со временем, токенами и стоимостью вызовов.
Нужны ключ API и личная инструкция. Без API этот шаг проверяется учебными
ответами в тестах, а не выдаёт выдуманный настоящий профиль.

### Шаг 3. Проверка и утверждение вопросов

**Вход:** профиль и вопросы шага 2.

**Действия:** пользователь проверяет названия, категорию и вопросы на локальной
странице, исправляет их и при необходимости добавляет до 10 своих.
Проверяются пустые поля, длина, повторы и правила брендовых вопросов.
Утверждение человеком не обходится автоматически.

**Выход:** `private/step3/PROJECT/`: утверждённые `profile.json`, `prompts.json`
и `step4_input.json` с контрольной суммой вопросов.
После изменения вопросов нужна новая согласованная выгрузка.
Контрольная сумма проверяет согласованность файлов, а не личность автора.

### Шаг 4. Сбор ответов моделей

**Вход:** `step4_input.json`, выбранные системы, ключи и явный предел расходов.

**Действия:** вопросы отправляются без предыдущей истории разговора.
Предусмотрены ChatGPT, Gemini, Claude, DeepSeek и Perplexity; настройки
находятся в исходном `tools/step4_collect.py`.
По умолчанию берутся три повтора, а при расхождении признаков — до пяти.
`--repeats N` задаёт фиксированное число повторов. Предусмотрены повтор после
ограничения частоты и дозапрос ошибок через `--retry-errors`.

**Выход:** `private/step4/PROJECT/answers.jsonl`, `step4_report.json` и сжатые
исходные ответы в `raw/` с контрольными суммами. Сохраняются текст, источники,
система, модель, номер повтора, статус, расходы и время.
Ошибка или пропуск не превращаются в ответ «компания не упомянута».

`--dry-run` показывает план без отправки запросов. Для настоящего сбора
обязателен `--max-cost` или `--max-cost-per-system`.
Оценка сборщика не является гарантией будущей цены поставщика.

### Шаг 5. Разбор сохранённых ответов

**Вход:** утверждённый `step4_input.json`, соответствующий `profile.json`
и журнал `answers.jsonl` шага 4.

**Действия:** проверка формата и контрольной суммы; преобразование записей;
поиск явных названий, ссылок и источников. Для сочетания «вопрос, система,
номер повтора» берётся последняя запись. История замен сохраняется.
Вопросы распределяются по уровням A–D. Сборщик не вызывается,
сжатые исходные ответы API не распаковываются.

Система исключается из измерения, если доля ошибок и пустых ответов среди
предпринятых попыток **больше 20 %**. Ровно 20 % не исключает её.
Пропуски по бюджету в этот знаменатель не входят; система без предпринятых
попыток исключается. Её данные остаются доступны для просмотра.

**Выход:** `bundle/` и `step5/`: исходные снимки, история попыток,
`mechanical.jsonl`, `intake.jsonl`, `summary.json`, отчёт, группы вопросов
и категории оснований. Внутренний модуль шага 5 отделяет неправильные
и конфликтующие строки в карантин. Несогласованный экспорт исходного
сборщика отклоняется целиком до записи готового результата.

### Шаг 6. Присутствие и роль компании

**Вход:** проверенная публикация шага 5.

**Действия:** локальные правила определяют, относится ли упоминание к нужной
компании, предлагают ли её как вариант, отговаривают ли от выбора и указан ли
явный ранг. Решения: `yes`, `no`, `uncertain` — «да», «нет», «неясно».
Найденное слово само по себе не доказывает рекомендацию. Другие имена
из списков и таблиц — кандидаты, а не подтверждённый полный список конкурентов.

Положительные решения сопровождаются точными цитатами и их положениями
в исходном тексте. Заголовок списка и сама строка сохраняются раздельно.
Неоднозначности одного ответа объединяются в одно модельное задание.

**Выход:** `annotations.jsonl`, `semantic_jobs.jsonl`, `summary.json`,
`quality.json`, отчёт и исходные снимки. В автономной команде анализа модельные задания не выполняются:
`executed=false`, вызовов нет. Неясные случаи остаются неясными.

### Шаг 7. Независимая выборочная проверка

**Вход:** разметка шага 6; необязательно — отдельно подготовленный файл
результатов внешней проверки.

**Действия:** отбираются пригодные спорные ответы и случайные 5 % пригодных
ответов, с округлением вверх и фиксированным начальным значением генератора.
Пересечение не создаёт двойных заданий. Проверяющему предназначен только
`blind_jobs.jsonl`: без первичной разметки и причины отбора.
Проверяются идентичность компании и роль бренда.

Принятый результат уточняет только `uncertain`. Уверенные решения случайная
выборка не переписывает: расхождения учитываются отдельно. Неверные цитаты,
чужие задания и конфликтующие версии попадают в карантин. Учебная проверка
не создаёт настоящую оценку надёжности.

**Выход:** `selection.json`, `blind_jobs.jsonl`, `crosscheck.jsonl`,
`resolved_annotations.jsonl`, `agreement.json`, `review_intake.jsonl`,
`quarantine.jsonl`, сводка и отчёт. Без внешних результатов `crosscheck.jsonl`
пуст, согласие равно `null`, надёжность не оценена. Это ожидаемое состояние,
а не выполненная независимая проверка.

При достаточной модельной выборке согласие от 90 % даёт среднюю надёжность,
ниже 90 % — низкую. По умолчанию нужны не менее 20 сравнимых пар и 20 разных
ответов, а также покрытие не менее 80 % проверяемых позиций; иначе данных
недостаточно. Подробности: [шаг 7](docs/STEP_7.md).

### Шаг 8. Варианты названий и источники

**Вход:** публикация шага 7; необязательно — явный справочник названий
и типов доменов через `--catalog`.

**Действия:** применение допустимых уточнений шага 7; объединение вариантов
по регистру, Unicode и пробелам; группировка ссылок по точному имени хоста.
Целевая компания, другие кандидаты и неразрешённые названия не смешиваются.
Похожее написание или транслитерация создают предложение на проверку,
но не доказывают, что это одна компания. Неизвестный тип источника
не угадывается. Сайты не открываются.

**Выход:** `brand_map.json`, `brand_occurrences.jsonl`, `domain_types.json`,
`unresolved_entities.jsonl`, сводка, сведения о качестве и отчёт.
Повторные упоминания бренда в ответе не превращаются в несколько ответов.
Незавершённые проверки отмечаются как ограничения результата.

## Завершение шагов 9–12

В отдельной ветке `feature/steps-9-12` реализовано продолжение без новых зависимостей и вызовов моделей.

| Шаг | Вход | Что делает | Выход |
| --- | --- | --- | --- |
| 9 | Результат шага 8; необязательно — проверенный обход сайта | Среднее по вопросам, повторная выборка вопросов, устойчивость, названия и источники | `aggregates.json`, `answer_metrics.jsonl` и основания расчётов |
| 10 | Расчёты и подтверждённые цитаты страниц | Отбор тем без упоминаний, предварительная группировка и одно ограниченное задание модели | `gaps.json`, `gap_jobs.jsonl`; без API готовый текст не выдумывается |
| 11 | Расчёты, проверки сайта и темы | До четырёх находок и план по периодам, только с основаниями | `findings.json`, `plan.json`, категории оснований |
| 12 | Проверенные результаты предыдущих этапов | HTML-отчёт, сверка чисел, пояснение отсутствующих данных | `report.html`, `report_data.json`, `validation.json` |

```sh
python run.py finish --chain-dir private/complete/PROJECT --output-dir private/final/PROJECT
python run.py finish --verify private/final/PROJECT
```

На macOS/Linux используйте `python3`. Итоговый файл: `private/final/PROJECT/report.html`.
Добавьте `--site-dir private/runs/STEP1_PUBLICATION`, чтобы включить технические проверки
и подтверждённые цитаты для подготовки содержания. Без них соответствующие блоки
объясняют отсутствие данных. Для отдельного результата шага 8 используйте `--step8-dir`.

Основные доли усредняются по вопросам, а не по всем ответам сразу: дополнительные
повторы не увеличивают вес вопроса. Отсутствующие значения остаются `null`.
Неясные рекомендации исключаются из своего знаменателя и показываются отдельно.
Повторная выборка выполняется кодом, по умолчанию 400 раз с фиксированным начальным
значением генератора; это описательный разброс по выбранным вопросам.

Модельное задание шага 10 ограничено 24 000 символами и 1600 токенами ответа.
Без тем оно не создаётся. Импортированные тексты проверяются по страницам, цитатам,
фактам и числам, но остаются заготовками для проверки человеком.
В автономной команде `finish` ключ ничего не запускает. Веб-режим `ui --live`
подключает ограниченную перепроверку и подготовку материалов; см. начало README.

Посещение до пяти внешних страниц вынесено в отдельную команду `run.py sources`,
которая требует `--allow-network`. Учебный и обычный локальный расчёт её не вызывают.
Полные команды, ограничения и форматы: [шаги 9–12](docs/STEPS_9_12.md).

## Уровни вопросов и четыре категории оснований

Это две разные разбивки:

| Уровень вопроса | Назначение |
| --- | --- |
| A | Простой запрос о лучших вариантах |
| B | Задача и ограничения клиента |
| C | Выбор, сравнение и короткий список |
| D | Исследование рынка и проверка источников |

| Категория основания | Значение |
| --- | --- |
| Наблюдаемый факт | То, что прямо обнаружено в данных, с проверяемым основанием |
| Расчётная оценка | Число, рассчитанное по фактам, с допущениями и ограничениями |
| Гипотеза | Возможная причина, которую данные не доказывают |
| Рекомендация | Предлагаемое действие с основанием и ограничениями, без обещания роста |

Уровень D не означает «гипотеза». Фраза модели «рекомендую компанию»
не является рекомендацией самого аудита. Один ответ нельзя целиком
и безусловно отнести только к одной категории оснований.

В `step5/categories/` создаются четыре файла и `index.json`.
На шаге 5 заполняются наблюдаемые факты; расчётные оценки, гипотезы
и рекомендации остаются пустыми с пояснением `not_produced_at_step5`.
Это не означает отсутствие рекомендаций компании в ответах моделей.
Шаги 5–8 не создают итоговые доли. На шаге 9 они рассчитываются с явными знаменателями, покрытием и ограничениями.

## Обработка своих сохранённых ответов без API

Нужны согласованные файлы исходного сборщика:

```text
private/step3/PROJECT/profile.json
private/step3/PROJECT/step4_input.json
private/step4/PROJECT/answers.jsonl
```

Замените `PROJECT` своим именем папки:

```sh
python run.py analyze --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT
python run.py verify private/complete/PROJECT
```

На macOS/Linux используйте `python3`. Другой профиль задаётся через `--profile ПУТЬ`.
Для вымышленных данных добавьте `--synthetic`. Частичный сбор можно обработать
явным вызовом `analyze`. Пустой журнал не принимается как готовый сбор.

Папка результата должна быть **новой и отдельной от входных папок**:
нельзя использовать ту же папку, её родителя или вложенную папку.
Это проверяется до записи; в команде `collect` — ещё до платного сбора.
Небезопасные файловые ссылки и неподдерживаемые пути отклоняются.
Для повторного разбора выберите новое имя папки.

```text
private/complete/PROJECT/
  bundle/          входы, преобразованные данные и история попыток
  step5/           названия, ссылки, уровни и категории оснований
  step6/           первичная разметка и точные цитаты
  step7/           выборка, внешний контроль и уточнения
  step8/           объединённые названия и источники
  report.html      общая страница со ссылками на шаги
  chain.json       признак завершённой записи всей цепочки
```

`bundle/source_links.jsonl` связывает внутренние записи со строками сборщика;
`bundle/attempts.jsonl` хранит историю замен; `bundle/summary.json` перечисляет
исключённые системы и несобранные вопросы.

`verify` проверяет размеры и контрольные суммы, воспроизводит результаты
из входных снимков и сверяет связь соседних шагов. Проверка не использует сеть
и ничего не исправляет молча. Она выявляет несогласованные изменения,
но не удостоверяет подлинность внешнего API и правильность смысловых выводов.
После ошибки незавершённая папка может остаться на диске; без `chain.json`
она не считается готовой цепочкой. Для нового запуска нужна новая папка.

Дополнительные параметры `analyze`: `--reviews private/reviewer-results.jsonl`
и `--catalog private/entity-catalog.json`. Форматы описаны в
[шаге 7](docs/STEP_7.md), [шаге 8](docs/STEP_8.md) и [schemas](schemas).

## Настоящий запуск от сайта до ответов

Это инструкция для будущего настоящего запуска. Техническая проверка обращается
к сайту; подготовка профиля и сбор ответов требуют API и могут расходовать деньги.

1. Сохраните личную инструкцию в
   `private/prompts/prompt_step2_profile_and_queries.md`.
2. Скопируйте `.env.example` в `private/.env`, заполните нужные ключи и передайте
   их процессу через переменные окружения. `run.py` не читает этот файл автоматически.
   Для явной загрузки можно использовать
   `uv run --env-file private/.env --locked python tools/steps0_8.py ...`.
   Ключи не публикуются. Для шага 2 нужен `ANTHROPIC_API_KEY`, для шага 4 —
   ключи выбранных систем из `.env.example`.
3. Выполните шаги 0–2:

```sh
python run.py prepare https://YOUR-SITE --country Россия
```

4. Проверьте вопросы на локальной странице шага 3:

```sh
python run.py review private/step2_fast/PROJECT
```

По умолчанию адрес страницы — `http://127.0.0.1:8766`.
Нажмите «Проверить», исправьте ошибки, затем «Сохранить».
Завершите работу локального сервера перед следующей командой.

5. Посмотрите план без отправки запросов:

```sh
python run.py collect --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT --dry-run
```

6. Для настоящего сбора выберите системы и предел расходов.
   Вместо `LIMIT` укажите выбранную сумму в долларах:

```sh
python run.py collect --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT --systems chatgpt gemini claude --max-cost LIMIT
```

После успеха сборщика шаги 5–8 выполняются автоматически. После ошибки сбора
они сами не запускаются. Для дозапроса ошибок есть `--retry-errors`;
для последующего анализа выберите новую папку результата.
Действующие цены, доступность моделей и параметры API нужно сверять перед
настоящим запуском; сохранённый код не гарантирует их неизменность.

## Отдельная техническая проверка сайта

```sh
python run.py audit https://YOUR-SITE
python run.py serve
```

`audit` выполняет шаги 0–1. `serve` запускает локальный технический интерфейс
на `http://127.0.0.1:8765`, где сайт задаётся пользователем.
Это существующий интерфейс технической проверки, а не готовый интерфейс
всей цепочки 0–8 на React. Одновременно обрабатывается один аудит.
Результаты по умолчанию сохраняются в `private/runs/`.

Другие команды пакета: `geo-audit step1`, `recommend`, `load-step2`.
Синтаксис: `python run.py audit --help` и
`.venv\Scripts\python.exe -m geo_audit --help` на Windows;
на macOS/Linux — `.venv/bin/python -m geo_audit --help`.

## Безопасность и скорость

- Назначение подключения проверяется до обращения. Используется закреплённый
  числовой IP с проверками фактического адреса, имени сервера и сертификата TLS.
- Соблюдаются `robots.txt`, ограничения времени, попыток и задержки. По умолчанию
  шаги 0–1 ограничены 300 секундами и 150 попытками, шаг 0 — 60 секундами
  и 15 попытками; выбирается не более 30 страниц.
- Карта сайта, CDN и canonical не расширяют разрешённую область обхода.
  CAPTCHA, вход на сайт и запреты роботов не обходятся.
- Работа через браузер по умолчанию отключена. Без проверенного безопасного
  подключения возвращается `unknown/SAFE_EGRESS_UNAVAILABLE`.
- На шагах 5–8 нет сетевых обращений. Тексты ответов рассматриваются как данные;
  содержащиеся в них инструкции и команды не выполняются.
- Сохраняются ограничения размеров, безопасное чтение, атомарная запись,
  точные цитаты и проверка целостности. Папки результатов новые,
  `manifest.json` записывается последним.
- Повторный разбор одинаковых данных шагов 6–7 переиспользуется только внутри
  одной операции, с пределом памяти 64 MiB. Изменение входа не использует старый
  результат. Проверки файлов не пропускаются.
- Неясности одного ответа и пересечение выборок не создают повторных заданий.
  Модельные исполнители шагов 6–8 пока отключены.

## Проверки для разработки

После `setup` установлены зависимости программы. Для тестов нужны также
зависимости разработки. Используйте закреплённый установщик:

```powershell
.bootstrap\Scripts\python.exe -m uv sync --locked
```

На macOS/Linux: `.bootstrap/bin/python -m uv sync --locked`.
Если uv уже установлен отдельно, достаточно `uv sync --locked`.
Основные проверки на Windows:

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest -q -ra
.venv\Scripts\python.exe -m ruff check src tests tools run.py
.venv\Scripts\python.exe -m mypy --platform win32
.venv\Scripts\python.exe -m mypy --platform linux
.venv\Scripts\python.exe -m bandit -r src
.venv\Scripts\python.exe -m bandit -r tools run.py -s B101,B311
.venv\Scripts\python.exe tools/generate_step0_artifacts.py --check
.venv\Scripts\python.exe tools/generate_step1_artifacts.py --check
```

На macOS/Linux замените `.venv\Scripts\python.exe` на `.venv/bin/python`.
В учебных генераторах намеренно используются `assert` и воспроизводимая
случайная выборка: исключения Bandit относятся только к этим двум проверкам
служебных инструментов. Проверки рабочего кода не ослабляются.

[Проверки GitHub](https://github.com/al7xey/geo/actions) выполняются на Windows,
macOS и Linux: полный набор тестов, настоящие локальные TCP/TLS-соединения,
проверки запрещённых направлений и файловых ссылок, типы, стиль, безопасность,
схемы, зависимости, сборка и установленный пакет. Отдельно проверяются
установка через `run.py`, учебный прогон и сохранённый результат.
Тесты не запускают платные API и аудит публичных сайтов.

Код `0` команды `analyze` или `verify` означает корректную публикацию или
проверку файлов. Внутри могут оставаться `partial` и `pending_api_key`:
это не обещание завершённой смысловой проверки. Некорректный ввод возвращает `2`.
Отдельные команды шагов имеют свои коды, описанные в их документации;
технический аудит различает частичный результат, недостаток данных и ошибку записи.

## Структура проекта

```text
run.py                  общий запуск на разных системах
src/geo_audit/          рабочий код и отдельные модули step5–step8
tools/                 программы шагов 2–4, связка и учебные генераторы
tests/                 проверки и управляемые тестовые серверы
schemas/               описание форматов данных
examples/              вымышленные примеры и учебные ответы
docs/                  подробные инструкции
private/               личные инструкции, ключи и результаты; не входит в Git
```

В Git хранятся код, тесты, схемы, учебные примеры и настройки проверок.
Личные документы, инструкции, ключи и результаты аудитов остаются в `private/`.
Установочный пакет содержит рабочий код, список доменных зон и метаданные.
Команды `run.py` и `tools/` рассчитаны на папку исходного проекта;
после установки только пакета шаги 5–8 доступны через
`python -m geo_audit.step5.workflow`.
