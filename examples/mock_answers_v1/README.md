# Синтетические ответы GEO-аудита: 480 записей

Это вымышленные тестовые данные, а не ответы OpenAI, Anthropic или Google и не аудит GoGetLinks. Все рекомендации, отрицательные отзывы и сравнения придуманы для проверки обработки. Не использовать их для оценки реальных сервисов.

## Состав

- 20 вопросов по фотографиям: 5 базовых, 5 с контекстом, 5 на выбор/сравнение, 5 исследований.
- 3 имитируемые системы: mock_openai, mock_anthropic, mock_google.
- 8 повторов каждого вопроса в каждой системе: 20 × 3 × 8 = 480.
- По 120 записей в каждой группе A–D и по 160 на систему.
- 445 полных текстов, 15 пустых ответов, 12 ошибок, 8 оборванных ответов.
- 32 сценария: рекомендации, отрицательные и смешанные роли, нейтральные упоминания, отсутствие компании, кириллица, аббревиатура, местоимение, чужая цитата, сложное отрицание, ссылка только в источниках, ложные домены, отказ, ответ не по теме, инструкция внутри данных и технические ошибки.

Это шаблонный корпус с вариациями контекста, а не 480 независимых рассуждений модели. Он проверяет корректность и воспроизводимость обработки. Качество классификации на реальных ответах, репрезентативность рынка и фактическую скорость API по нему измерять нельзя. Часть ответов намеренно не выполняет запрос полностью, например не выдаёт топ-10.

Для быстрого просмотра: `PREVIEW.md` — четыре пары вопрос/ответ; `EXPECTED_METRICS.md` — таблица эталонных процентов по группам и системам.

## Что передавать программе

Только файлы из `input/`:

| Файл | Назначение |
| --- | --- |
| prompts.json | Тексты вопросов, ID и группы |
| target.json | Названия целевой компании и тестовый домен |
| answers.jsonl | 480 исходных записей, одна на строку |

В ответах нет поля с ожидаемым сценарием, ролью или результатом классификации. Поле group дано для удобства экспорта; программа должна сверить его с группой исходного вопроса. Домены заканчиваются на `.test`; открывать их не нужно. В target_cited проверяется только тестовый домен из target.json, не настоящий сайт компании.

Не передавать классификатору/модели папку `oracle/`: это правильные ответы для тестов, а не входные признаки.

## С чем сравнивать результат

| Файл | Назначение |
| --- | --- |
| oracle/expected_decisions.jsonl | Эталонные признаки, роли, цитаты и неоднозначности |
| oracle/expected_aggregates.json | Micro и macro по системе, группе и вопросу, общий итог |
| oracle/expected_review_selection.json | Эталон случайной выборки 5% и всех uncertain |
| groups/A.jsonl … D.jsonl | Эталон распределения ID по четырём группам |
| manifest.json | Состав, seed, SHA-256 файлов |

Показатели presence/recommended/discouraged/cited независимы. Для смешанного совета положительная и отрицательная рекомендация могут обе быть yes. uncertain не означает no. Технически непригодные записи имеют eligible=false и признаки null, не участвуют в знаменателе. Отказы и ответы не по теме входят в знаменатель по выбранной политике этого корпуса.

Macro — среднее по наблюдаемым парам «система × вопрос» после исключения ошибок. Micro — доля по всем пригодным ответам. Они могут различаться, потому что технические ошибки делают число пригодных повторов неодинаковым. Для сравнения нескольких систем на других данных нужно отдельно учитывать общий набор вопросов и веса систем.

В expected_review_selection seed используется для воспроизводимой выборки. Это ожидаемое задание, не выполненная проверка нейросетью. Реальную очередь ваш обработчик должен строить по своим uncertain, а не читать их из oracle.

## Воспроизведение из корня репозитория

```powershell
.\.venv\Scripts\python.exe tools\generate_mock_answers.py
.\.venv\Scripts\python.exe tools\validate_mock_answers.py
```

Оба скрипта используют только стандартную библиотеку Python. Нужны Python 3.12+ и возможность записать синтетические файлы примера; API-ключи, браузер и сеть не используются. Генератор обновляет только известные файлы набора, не очищает каталог рекурсивно. Ручные правки сгенерированных JSON при следующем запуске будут заменены; для собственного набора используйте другой каталог/версию генератора.

Проверка сверяет 480 записей, логические слоты, ссылки на вопросы, четыре группы без потерь и пересечений, цитаты и позиции, тестовые домены, ожидаемые проценты, случайную выборку и хеши. Это проверка фикстур; промышленный обработчик шагов 5–12 пока не реализован.
