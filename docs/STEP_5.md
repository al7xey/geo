# Шаг 5: механический разбор собранных ответов

Автономный модуль `geo_audit.step5`. Не обращается к сайтам и нейросетям, не требует API-ключей. Принимает файловый экспорт, сохраняет исходники и публикует результаты в **новую** папку. Существующие шаги 0–4 не запускаются и не изменяются.

Для предоставленного сборщика реализован переход `geo_audit.step5.workflow`:
утверждённые вопросы и профиль шага 3 вместе с ответами шага 4 поступают в
шаги 5-8. Подробности: [INTEGRATION_0_8.md](INTEGRATION_0_8.md).

## Четыре категории результатов

Категории из требований пользователя — это типы оснований аудита:

| Файл | Значение на шаге 5 |
| --- | --- |
| categories/observed_fact.jsonl | Проверяемые наблюдения о полученных записях и совпадениях текста |
| categories/calculated_estimate.jsonl | Пустой: процентные оценки появятся на шаге 9 |
| categories/hypothesis.jsonl | Пустой: причинные предположения на этом шаге не создаются |
| categories/recommendation.jsonl | Пустой: рекомендации аудита создаются позднее |

`categories/index.json` содержит статус и количество для каждой категории. Пустые файлы означают `not_produced_at_step5`, а не «не найдено ни одной рекомендации в ответах моделей».

Наблюдаемый факт: **в данном ответе есть конкретная строка**, с цитатой и позициями. Это не подтверждение правдивости утверждения модели, идентичности компании или её реальных свойств. Даже фраза «рекомендую X» на этом этапе является только найденным текстом, а не рекомендацией самого аудита.

Уровни запросов A–D остаются отдельной осью в `prompt_groups/A.jsonl` … `D.jsonl`. Это не указанные выше четыре категории и не автоматическая оценка содержимого ответа. Один ответ может впоследствии дать основания нескольким категориям; весь ответ нельзя безусловно считать фактом или гипотезой.

## Запуск из корня проекта

```powershell
.\.venv\Scripts\python.exe -m geo_audit.step5 `
  --input-dir examples/mock_answers_v1/input `
  --output-dir private/step5-demo-001
```

Папка результата должна отсутствовать. Для повторной проверки используйте новое имя, например `step5-demo-002`; модуль не перезаписывает ранее опубликованные данные. Одинаковые входы дают одинаковое содержимое файлов независимо от имени папки. Это не кеширование повторного запуска: оно относится к дальнейшей оркестрации.

### Просмотр результата

Откройте `report.html` внутри новой папки результата обычным двойным щелчком. Он работает с локального диска без сервера: показывает вопросы, полные тексты ответов, подсвеченные совпадения, неоднозначные варианты и источники. Есть поиск и фильтры по системе, группе A–D, статусу доставки и виду найденного сигнала. Записи раскрываются отдельно; без JavaScript тексты также доступны, только фильтрация отключена.

Страница явно помечает наличие синтетических данных. Четыре категории оснований показаны отдельно от уровней вопросов; нулевые оценки/гипотезы/рекомендации сопровождаются пояснением «следующие этапы». Это просмотр результата шага 5, не финальный отчёт и не смысловая разметка рекомендаций.

HTML содержит только встроенные CSS и фиксированный скрипт фильтрации. CSP разрешает именно их по SHA-256, запрещает внешние ресурсы и сетевые обращения; пользовательский текст экранируется. Адреса источников показываются текстом и автоматически не открываются.

### Проверка сохранённой публикации

```powershell
.\.venv\Scripts\python.exe -m geo_audit.step5 --verify private/step5-demo-001
```

Проверяются commit marker, версия, допустимый набор артефактов, размеры и SHA-256. Затем обработка воспроизводится из сохранённых исходных снимков, и все результаты, включая HTML и категории, сравниваются побайтно. Так обнаруживается не только случайная порча, но и несогласованная правка результатов вместе с их хешами. Проверка ничего не записывает, не открывает пути, полученные из manifest, и не делает сетевых запросов.

Это проверка целостности и согласованности, не доказательство подлинности ответов поставщика и не независимая смысловая проверка шага 7. Она поддерживает текущие публикации `step5-publication-1.1` / `step5-rules-2`; ранние демонстрационные публикации нужно заново построить из исходного input в новую папку. Успешный `--verify` возвращает 0 даже для корректно опубликованного partial-результата; повреждение возвращает 2.

Коды завершения: `0` — все записи приняты или корректно распознаны как повторный импорт; `1` — часть строк помещена в карантин, результат опубликован; `2` — ошибка справочника, чтения, лимитов или записи, законченной публикации нет. Наличие error/empty/truncated в исходных ответах само по себе не является ошибкой импорта: эти статусы сохраняются.

Пустой вход и отсутствие принятых ответов также дают partial и код 1, с предупреждением no_accepted_answers. Количество неоднозначных совпадений и пропущенных некорректных URL включено в summary; эти наблюдения не выдаются за доказанные упоминания.

## Входной формат

Три файла в одной папке: `prompts.json`, `target.json`, `answers.jsonl`. Точные JSON Schema находятся в `schemas/step5/`; рабочий синтетический пример — в `examples/mock_answers_v1/input/`.

Обязательные поля вопроса: prompt_id, group (A/B/C/D), text, visibility_eligible. Набор содержит schema_version="1.0", prompt_set_id, country, language и prompts. Неактивный вопрос отмечается active=false. Группа определяется справочником, а не номером или текстом ответа.

Target содержит target_id, name, aliases, ambiguous_aliases, domains. Домены задаются hostname, без схемы, порта и пути. Неоднозначные варианты должны присутствовать в aliases. Подтверждённые домены также покрывают свои поддомены при сопоставлении URL; это вычисление, не сетевое разрешение на их посещение.

Обязательные поля ответа: answer_id, prompt_id, prompt_set_id, provider, model, origin, repeat_index, search_mode, status, text. Для origin=synthetic обязательно synthetic=true. Допускаются nullable метаданные и sources согласно схеме; неизвестные поля не принимаются молча. Для ручного происхождения используется origin=manual_chat, для реального API — api. Неизвестная модель задаётся строкой unknown, без выдуманных сведений.

Sources содержат url, origin и необязательный title. Структурно неверная запись источника отправляет ответ в карантин; структурно допустимый, но небезопасный/некорректный URL пропускается и увеличивает invalid_source_count. Учёт источников из API и URL основного текста разделён.

Это версия **внутреннего контракта**, а не обещание совместимости с неизвестным сборщиком другого репозитория. Для него понадобится тонкий адаптер полей. API-конверты и raw_ref не открываются, не распаковываются и не интерпретируются как пути.

## Что извлекается

- Точные варианты названия с Unicode NFKC/casefold и границами слов; регистр не влияет, короткие варианты помечаются ambiguous. Эвристические окончания и fuzzy не включены, чтобы не создавать ложных совпадений.
- Исходная цитата, позиции в Unicode code points (как индексы Python), location=body/text_url. JavaScript использует UTF-16, поэтому его индексы нельзя применять без преобразования.
- HTTP(S) URL текста и citations; hostname в IDNA-формате, registrable domain по локальному PSL и признак известного суффикса. При неизвестном суффиксе psl_known=false; registrable_domain не выдаётся за подтверждённую регистрационную границу.
- target_name_candidate, target_domain_in_body, target_domain_in_citations — раздельные механические сигналы. Название только внутри URL не становится кандидатом имени в содержательном тексте.
- Каждый URL остаётся resolution_status=not_attempted. Переадресации не разворачиваются; зафиксирован только наблюдаемый адрес, а не проверенный конечный сайт.

На этом этапе нет проверки рекомендаций, тональности, неявных компаний и достоверности текста; annotation_status=unreviewed. Цитаты чужого текста/инструкции внутри ответа не исполняются, а их смысл оценивается позднее. `GoGetLinksPlus`, короткое неоднозначное `GGL` и цитирование домена не равны доказанному присутствию целевого бренда.

URL нормализуется только для локальной дедупликации, не для посещения: hostname/схема, стандартный порт и пустой путь. Параметры, фрагменты и исходный текст не удаляются из первичных данных. Credential-bearing, не-HTTP(S) и неоднозначные URL не допускаются в извлечённые источники. Источник с совпавшим доменом означает только наблюдение домена URL, не проверку доступности/содержимого страницы.

## Результат

```text
result/
  input/prompts.json            # точные байты исходников
  input/target.json
  input/answers.jsonl
  mechanical.jsonl             # производные наблюдения по принятым ответам
  intake.jsonl                 # исход каждой физической строки
  quarantine.jsonl             # ссылки на отклонённые строки и причины
  prompt_groups/A.jsonl ... D.jsonl
  categories/observed_fact.jsonl
  categories/calculated_estimate.jsonl
  categories/hypothesis.jsonl
  categories/recommendation.jsonl
  categories/index.json
  summary.json
  validation.json
  report.html                  # локальный просмотр с поиском и фильтрами
  manifest.json                # последний commit marker с SHA-256/размерами
```

Общий secure storage также создаёт пустой служебный каталог raw/. Полные тексты не копируются в каждый индекс: source_line указывает на строку `input/answers.jsonl`, text_sha256 связывает наблюдение с оригинальным текстом. Номера строк начинаются с 1. Карантин содержит ID/номер строки/хеш/код причины, без дополнительного копирования секретов или текста ошибки API.

HTML содержит производную копию текстов для автономного просмотра. Смысловые решения следующих шагов должны опираться на неизменённые input и mechanical, а не извлекаться обратно из HTML. citation_indices в каждом источнике указывает на исходные элементы sources (индексация с 0); text_spans — на URL основного текста. При неизвестном суффиксе registrable_domain=null, чтобы предположение о границе не выглядело установленным фактом.

Каждая физическая строка получает один исход: accepted / duplicate / quarantined. Завершающий LF не создаёт пустой записи; пустая внутренняя строка — повреждённая JSONL-запись. Повторная запись с тем же ID и тем же JSON-содержимым — duplicate. Конфликтующие версии одного ID отклоняются **все**, независимо от порядка. Разные ID в одном логическом слоте также отклоняются. Одинаковый текст разных повторов — разные наблюдения.

Логический слот включает набор, вопрос, provider/model, repeat_index, origin, search_mode, country/language и settings. Чтобы различать эксперименты с другими настройками, передавайте их явно. Если upstream не может представить эту связь, нужна правка адаптера, а не случайная дедупликация по тексту.

Публикация считается завершённой только после manifest.json. При обрыве записи каталог может остаться, но в нём не будет маркера готовности. Читатели следующих шагов должны проверять marker, хеши и версии до использования. Сейчас опубликованный каталог не переиспользуется и не редактируется.

## Лимиты и безопасность

До 10 000 строк, 64 MiB answers.jsonl, 1 MiB на строку, 500 000 символов текста ответа, 4 MiB на справочник, 1000 вопросов, 100 алиасов/доменов, 200 структурированных источников в ответе, до 2000 найденных URL и до 2000 совпадений названий на ответ. Превышение бюджета извлечения отдельного ответа — карантин; превышение общего входного/выходного бюджета — отказ до создания публикации. Общий выход до 256 MiB, один файл до 64 MiB.

Дополнительно весь проход ограничен 50 000 наблюдений (совпадений и источников) и 64 MiB сериализованных механических результатов. Эти лимиты проверяются при обработке, чтобы множество коротких повторяющихся совпадений не раздувало память без контроля.

Используются существующие confined I/O и атомарная запись проекта: запрет reparse/symlink-путей и hardlinked файлов, новая приватная папка, исходники только для чтения. Выход не может быть входом, его родителем или потомком. Нет сети, DNS, SDK, скачивания PSL, чтения произвольного raw_ref или исполнения текста. Неправильный вход не выводится целиком в сообщение CLI.

## Проверки и развитие

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_step5.py -q
.\.venv\Scripts\python.exe -m ruff check src/geo_audit/step5 tests/test_step5.py tools/generate_step5_schemas.py
.\.venv\Scripts\python.exe -m mypy src/geo_audit/step5
```

Проверяются полный мок-набор без DNS/сокетов и oracle, группы без потерь/пересечений, четыре категории, точные Unicode-цитаты, дубликаты/конфликты, ложные домены, citations отдельно от названий, статусы ошибок, лимиты, безопасный CLI, hardlinks, запрет перезаписи и отсутствие commit marker при сбое записи.

Схемы обновляются командой `python tools/generate_step5_schemas.py`; они хранятся в Git. Модуль не читает ожидаемые результаты из oracle и не выполняет следующие шаги. Для шага 6 будут использоваться исходные тексты, mechanical и раздельные признаки неоднозначности; для шага 9 — принятые смысловые решения, а не просто число кандидатов.
