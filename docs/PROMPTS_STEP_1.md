# Цепочка промптов для разработки шага 1

Подготовлено 01.11.2026 по рабочему алгоритму `docs/steps/STEP_1_ALGORITHM_v1.md` и реализации шага 0 версии 0.3.2. Это задания для будущей разработки, а не отчёт о выполненной реализации. Не обещают «идеальный» код: качество подтверждается проверяемыми критериями ниже.

## Что разрабатываем

Шаг 1 читает ограниченную часть сайта и готовит доказательный материал для профиля компании на шаге 2. Последовательность: проверенный handoff → robots → обнаружение URL → очередь → безопасное чтение → извлечение → технические проверки → достаточность → сохранение → проверяемый вход шага 2. Модели, платные API, генерация профиля и интерфейс сайта сюда не входят.

Шаг 0 уже реализует безопасную сеть, evidence, время, бюджет и Step1Handoff. Нельзя писать второй независимый HTTP-клиент или повторно загружать входной HTML ради старта. Нельзя использовать учебные JSON из PDF вместо актуальных контрактов. В текущем коде общий Budget связан со Step0Config, а типы версий — со step0: расширение требует совместимости, а не переименования всего пакета.

## Как применять цепочку

Выполнять промпты 1–13 последовательно. Для каждого нового чата сначала вставлять общий блок, затем один промпт. Продолжать следующий этап только после проверки результата предыдущего; незакрытые требования переносить явно. В одном чате общий блок можно дать один раз. Пути ниже относительно корня C:\GEO.

Это документационное поручение не запускает разработку, аудит сайтов или браузер. При последующем использовании промптов исполнитель действует в рамках соответствующего задания. Изменение методики отделять от исправления кода; спорный выбор, меняющий смысл результата, сначала оформлять как предложение.

```text

поддерживаемый Crawl-delay. Пределы ожидания общие.
Тестируй не только булев ответ parser, но точность evidence и отсутствие запрещённого
```
