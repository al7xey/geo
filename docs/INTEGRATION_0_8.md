# Шаги 0-8: связанная программа

Код шагов 0-4 взят из предоставленного архива без исправлений. Для передачи
их результатов добавлены только преобразование входа шага 5, выполнение шагов
5-8 и общая точка запуска. Первые шаги не заменены новыми алгоритмами.
Контрольные суммы исходного кода ранних шагов сохранены в
`docs/UPSTREAM_0_4_SHA256.json` и проверяются отдельным тестом.

## Если ответы уже собраны

Из папки проекта выполните:

```powershell
uv sync --locked
uv run --locked python tools/steps0_8.py analyze --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT
```

Замените `PROJECT` именем своей папки. Папка результата должна отсутствовать.
Программа использует утверждённый `profile.json` рядом с `step4_input.json`.
Если он лежит отдельно, добавьте `--profile ПУТЬ`.
Ни запросов к моделям, ни повторного чтения сайтов эта команда не делает.

В результате откройте `private/complete/PROJECT/report.html`. В нём ссылки
на результаты шагов 5, 6, 7 и 8. Исходные данные остаются без изменений.

Для проверки всех файлов сохранённой цепочки:

```powershell
uv run --locked python -m geo_audit.step5.workflow --verify private/complete/PROJECT
```

Это также работает после установки пакета, без запуска служебного скрипта:

```powershell
python -m geo_audit.step5.workflow --step4-input INPUT/step4_input.json --answers-dir ANSWERS --output-dir RESULT
```

## Если начинать с сайта

Эти команды используют исходные программы шагов 0-4. Подготовка профиля и сбор
ответов требуют действующих ключей доступа и могут расходовать деньги. Во время
разработки интеграции реальные платные вызовы не выполнялись.

1. Сохраните предоставленный личный промпт в
   `private/prompts/prompt_step2_profile_and_queries.md`. Он намеренно не хранится
   в Git. Ключи задайте переменными окружения по инструкции исходных шагов.
   Для ключей из `private/.env` можно явно передать uv параметр
   `--env-file private/.env` перед `python`. Ключи в Git не добавляются.
2. Выполните шаги 0-2:

```powershell
uv run --locked python tools/steps0_8.py prepare https://YOUR-SITE --country Россия
```

3. Проверьте профиль и вопросы на шаге 3:

```powershell
uv run --locked python tools/steps0_8.py review private/step2_fast/PROJECT
```

На странице исходной программы нажмите «Проверить», исправьте ошибки и нажмите
«Сохранить». Утверждение вопросов человеком не обходится автоматически.
После работы закройте локальный сервер проверки, чтобы перейти к следующей команде.

4. Сначала можно посмотреть план без отправки запросов:

```powershell
uv run --locked python tools/steps0_8.py collect --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT --dry-run
```

5. Для настоящего сбора явно задайте системы и предел расходов. Вместо `LIMIT`
   укажите выбранную сумму в долларах:

```powershell
uv run --locked python tools/steps0_8.py collect --step4-input private/step3/PROJECT/step4_input.json --answers-dir private/step4/PROJECT --output-dir private/complete/PROJECT --systems chatgpt gemini claude --max-cost LIMIT
```

После успешного сбора шаги 5-8 выполнятся автоматически. Если сбор остановился
с ошибкой, обработка сама не начинается. Для завершённой части данных можно
явно вызвать `analyze`. Ограничения расходов, повторов и параллельности исходного
сборщика передаются без изменений. Если нужен дозапрос ошибочных ответов,
добавьте исходный параметр `--retry-errors` и выберите новую папку анализа.

Перед платным сбором дополнительно проверяются наличие согласованного профиля,
контрольная сумма вопросов и новая папка результата. Папка результата не должна
совпадать с входными папками, находиться внутри них или включать их в себя.
Существующие участки путей проверяются безопасным способом без создания папок.
Недоступный корень диска отклоняется без бесконечного поиска родителя.
Это позволяет избежать
расходов, после которых обнаружилась бы обычная ошибка передачи данных.

## Что учитывается при передаче

- Принимаются 40 исходных вопросов и до 10 добавленных пользователем, а не только
  прежний учебный набор из 20. Поддерживается и частичный сбор.
- Уровни 1-4 становятся группами A-D. Тексты вопросов не переписываются.
- Признак `counts_in_organic_visibility` сохраняется. Вопросы с подсказкой
  названия компании не учитываются при измерении органической видимости.
- Сохраняются варианты названий и признак неоднозначности из утверждённого
  профиля шага 3. Если признак пропущен, название считается неоднозначным.
- Для пары «вопрос, система, номер повтора» берётся последняя запись, как в
  исходной функции `latest` шага 4. Предыдущие попытки остаются в журнале.
  Это относится и к замене ответа более поздним пропуском: удобный успешный
  ответ не выбирается вместо последней записи самовольно.
- Используются фактические названия систем, моделей и настройки ответа из
  строки сбора, без подстановки нынешних маршрутов моделей.
- Исключение системы пересчитывается по той же политике: больше 20 % ошибок
  или пустых ответов среди предпринятых, не пропущенных по бюджету, попыток.
  Ровно 20 % не исключает систему. Отсутствие таких попыток исключает её.
- Исключённая система сохраняется для просмотра, но её ответы получают
  `collection_eligible=false`. Они не попадают в измерение и выборку шага 7.
- Пропуск по бюджету становится непригодным ответом с отдельным кодом причины,
  а не отрицательным мнением о компании. Несобранные вопросы перечислены явно.
- Старые упрощённые признаки `mentioned` и `cites_site` не подменяют точную
  разметку шагов 5-6. Источники принимаются как уже объявленные сборщиком ссылки.
- Сжатые ответы API не открываются и не распаковываются. Их имя и контрольная
  сумма сохраняются для связи с исходником; достоверность внешнего вызова
  программа не выдаёт за независимо подтверждённую.

Ошибочный или противоречивый формат экспорта останавливает преобразование до
записи готового результата. Изменённые вопросы не принимаются без новой
контрольной суммы шага 3. Контрольная сумма проверяет согласованность данных,
а не удостоверяет личность того, кто их утвердил.

## Результат

```text
RESULT/
  bundle/          исходники шага 3/4, преобразованные файлы и журнал попыток
  step5/           названия, URL, группы вопросов и категории оснований
  step6/           идентичность, роли и точные цитаты
  step7/           независимая выборка и ожидающие проверки
  step8/           группы названий и типы источников
  report.html      общая страница просмотра
  chain.json       последний маркер завершённой цепочки
```

`bundle/source_links.jsonl` связывает новые ID со строками исходного файла,
`bundle/attempts.jsonl` показывает заменённые попытки, `bundle/summary.json`
содержит исключённые системы и несобранные вопросы. Личные результаты хранятся
только в игнорируемой папке `private/`.

## Скорость, проверки и оставшиеся ограничения

Обработка ответов выполняется локальным кодом. Все неоднозначности одного ответа
объединяются в одно задание, а случайная и спорная выборки не дублируют его.
Сжатые конверты API и посторонние файлы не читаются.

Дорогостоящий повторный разбор одних и тех же снимков шагов 6-7 переиспользуется
только внутри одной операции. Ключ зависит от точных байтов всех входов;
память ограничена 64 MiB и очищается после операции. Изменение входа не использует
старый результат. Каждый настоящий файл по-прежнему проверяется, а связи между
соседними шагами сверяются. При исчерпании памяти проверки просто выполняются
обычным способом, а не пропускаются.

Прежние ограничения размеров, точные цитаты, безопасная работа с файлами и
проверка воспроизводимости сохранены. Сетевые правила ранних шагов не менялись.

Общая команда запускает исходные программы с явным режимом UTF-8. Это важно
для русского текста на Windows и не требует изменений кода шагов 0-4.

`--synthetic` допустим для явно учебных исходников и сохраняет их происхождение
во всей цепочке; без него формат шага 4 считается объявленным API-экспортом.
Это объявление происхождения, а не наблюдение реального обращения из программы.

Независимые модельные исполнители шагов 6-8 пока остаются отключёнными.
Можно передать локальные проверки через `--reviews` и справочник шага 8 через
`--catalog`. Неопределённые случаи сохраняются; итоговые проценты и шаги 9-12
в эту реализацию не входят. Сама связка 0-8 не означает, что модели всегда
доступны по сохранённым в исходном сборщике адресам: реальные подключения здесь
не проверялись и настройки шагов 0-4 по вашему условию не менялись.
