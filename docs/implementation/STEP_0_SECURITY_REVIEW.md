# Security review шага 0

Начат 01.11.2026. Это проверка кода и воспроизводимого поведения; прежние отчёты
не принимаются как доказательство безопасности. Финальные результаты добавляются ниже.

## Модель угроз

Недоверенными являются ввод URL, DNS-ответы, каждый Location, HTTP-заголовки,
body/content-encoding и ранее сохранённый каталог запуска. Возможны SSRF, DNS rebinding,
подмена origin/scope, TLS identity bypass, gzip bomb, медленный поток, утечки query/cookies,
подмена артефактов через traversal/link/reparse/hardlink и прерывание публикации.
Нельзя считать данные сайта инструкциями, запускать JS/команды или десериализовать pickle.

Доверенные границы: код процесса, его настройки и локальный доверенный корень вывода,
стандартный SSL, ядро ОС и выбранный прямой маршрут. Администратор/root и субъект,
способный модифицировать сам исполняемый код/память процесса, вне этой модели.
Обычная конкурентная подмена имён/ссылок файлов внутри каталога должна блокироваться.

Проверки: независимые тесты URL/IP/peer/SNI, реальные локальные TCP/TLS-серверы,
контролируемые streams/time, race/link и corrupted-artifact fixtures, статическая проверка
Bandit и аудит зависимостей pip-audit. Нулевой вывод сканера не является оценкой всей архитектуры.

Подтверждённая исходная проблема для регрессии: evidence.py проверял resolve/stat,
а затем открывал файл по имени; ссылку можно заменить между проверкой и open.
Исправление требует дескрипторной проверки без следования ссылкам, а не повторного resolve.
