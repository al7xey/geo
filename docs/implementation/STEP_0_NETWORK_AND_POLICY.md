# URL, область и общий HTTP-клиент

Дата: 01.11.2026. Пакет 0.2.0, алгоритм реализации `step0-1.1`, схема `1.1.0`,
конфигурация по умолчанию `step0-config-1.1.0`. Поддержаны теги предыдущих контрактов;
сохранённый пример 1.0 проверяется отдельно. Правила источника PDF не переписаны.
Этот документ актуализирует сетевую часть первоначальной архитектурной записки.

## Что реализовано

`urls.py` нормализует ввод без сети и сохраняет `input_url` целиком. Без схемы выбирается
HTTPS; явно указанные HTTP/HTTPS сохраняются. `NormalizedURL` отдельно содержит ASCII и
Unicode host, origin, entry_path; port и scheme доступны свойствами. Query остаётся частью
URL с исходными порядком, повторами, `+`, пустыми значениями и регистром percent-escape.
Fragment удаляется. Unicode path/query кодируются в UTF-8 без NFC/NFKC-преобразования.

Исправлена прежняя проверка HTTPX «сам с собой»: ожидаемый request target строится
независимо через RFC quoting, затем сравнивается целиком с HTTPX, включая пустой `?`.
Сверяется также сериализованный URL и ASCII host. Нормализация идемпотентна для принятого URL.
Credentials, C0/C1/Unicode formatting controls, суррогаты, backslash, ошибочные host/port,
percent-escape и альтернативные IPv4-формы отклоняются. IDNA: UTS46 non-transitional/STD3.
После IDNA дополнительно проверяется числовой хост, включая полные Unicode-цифры.

`resolve_location` отдельно разрешает относительный Location, `..`, `.` и network-path
ссылки; сохраняет повторные slash и явно пустой query. Нельзя использовать обычный
`urljoin` без проверки этих инвариантов. Некорректный Location даёт REDIRECT_INVALID_LOCATION.

`scope.py`: build_scope, scope_reason, decide_redirect - чистые функции с явными входами.
Область состоит из точных хостов, отдельно разрешённых портов и необязательных префиксов
пути по границе сегмента. `/ru` не разрешает `/rub`; сам вход `/ru/entry` не вводит path_scope.
Разрешение хоста не является разрешением любого его поддомена и не снимает сетевые запреты.

`psl.py` работает с полным локальным PSL, включая private-секцию, wildcard и exception.
Снимок загружается только явным load_bundled_psl, сверяется SHA-256 и передаётся чистой
логике как неизменяемый объект. Исходная версия/commit/лицензия записаны в data/README.md.
Автоматический www разрешается только при наблюдаемом redirect, точной паре host/www.host,
одинаковом registrable domain и отсутствии suffix-only стороны. github.io/blogspot.com
сами не объединяются с www; www конкретного tenant допускается только внутри его границы.
Неизвестная PSL-зона не даёт автоматического алиаса: требуется явный allow-host.

`policy.py` содержит общие таблицы choose_next_action и classify_result, отдельный разбор
Retry-After и http_fallback_eligible. CLI и транспорт не реализуют собственные таблицы.
Повторяемые HTTP-статусы: 408/429/500/502/503/504; дополнительные попытки по умолчанию 1 и 2
секунды плюс неотрицательный jitter. Правильный Retry-After увеличивает ожидание, а не
уменьшает его; если ожидание не помещается в deadline, возвращается RETRY_DEFERRED.

Fallback - отдельный кандидат HTTP того же исходного host/path/query, максимум один.
Он возможен после разрешённого транспортного провала исходного HTTPS. Certificate failure
не повторяется; connect/read/timeout сначала проходят ограниченные retries. NXDOMAIN,
временный DNS, полученный HTTP-статус и подтверждённый барьер не меняют схему автоматически.
HTTP → ранее неисправный HTTPS останавливается до GET с FALLBACK_NO_USABLE_RESULT;
повтор посещённого URL - REDIRECT_LOOP. Переход HTTPS → HTTP сохраняется флагом downgraded.

Таблица финальных состояний находится также в предыдущей записке. classify_result принимает
готовые наблюдения, а не угадывает HTML по HTTP 200: ok/true только для полного пригодного
HTML с доказательствами; partial/true для fallback/downgrade/JS/разрешённой диагностики;
partial/false для непригодного 2xx; needs_input/false для безопасного внешнего хоста;
failed/false для ввода/назначения/хранения/окончательной сети/HTTP-ошибки.
Предыдущая ошибка TLS хранится историей, а не превращается в исправный HTTPS после fallback.

## Механизм фактического подключения

`connection.py` использует поддерживаемые точки расширения: httpx.AsyncBaseTransport,
httpcore.AsyncConnectionPool(network_backend=...), httpcore.AsyncNetworkBackend и
httpcore.AnyIOBackend. В приватные поля HTTPX не подставляется собственный pool.
TLS выполняет стандартный AnyIO/Python SSL; собственных TLS-протоколов или сертификатных
проверок нет. HTTP Core, AnyIO и Certifi теперь прямые зафиксированные зависимости.

1. check_endpoint получает все A/AAAA через Resolver; IP-literal проверяется без DNS.
   Mixed public/private ответ целиком отклоняется. Проверяются private, loopback,
   link-local, reserved, unspecified, multicast, site-local, mapped IPv4 и служебный
   168.63.129.16; зарезервированные translation-префиксы не проходят public-only policy.
2. PinnedBackend передаёт нижнему AnyIOBackend **числовой проверенный IP**, а не hostname.
   Между проверкой DNS и соединением нет второго разрешения hostname. Используется один
   адрес на попытку; автоматического перебора IP/Happy Eyeballs нет.
3. Сразу после TCP проверяется фактический peer IP **и порт**. Несовпадение/недоступность
   peer даёт TARGET_DNS_REBINDING до TLS и до HTTP-байтов, сокет закрывается.
4. Для HTTPS HTTP Core сохраняет исходный origin host как server_hostname. Guard проверяет
   исходное имя, check_hostname=True и CERT_REQUIRED и делегирует TLS обычному SSL backend.
   HTTP Host формируется HTTPX из исходного URL, а не из закреплённого IP.
5. Каждый GET имеет отдельный pool: retries=0, max_connections=1,
   max_keepalive_connections=0, http2=False, proxy=None. Даже если сервер предлагает
   keep-alive, соединение не используется следующим запросом. Следующий GET заново
   проверяет DNS. Новый pool не получает cookies предыдущего; redirects обрабатывает наш код.

Proxy-маршруты сейчас не реализованы: явный proxy вызывает TARGET_SECURITY_UNAVAILABLE.
Не выполняется небезопасный fallback на proxy или обычный HTTPX-клиент. trust_env=False,
default CA явно взят из закреплённого Certifi; HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY и
SSL_CERT_FILE/SSL_CERT_DIR не меняют этот режим. Пользовательский SSLContext допустим
только с проверкой цепочки и hostname; это доверенная конфигурация приложения, не настройка сайта.

Это защита выбранного прямого маршрута на границе приложения. Она не является гарантией
корректности ОС, DNS-провайдера, интернет-маршрутизации или прозрачного NAT в инфраструктуре.
Невозможность подтвердить peer/режим TLS заканчивается явной ошибкой.

## Поток, бюджет и закрытие

`SafeHttpClient.get` работает последовательно и возвращает FetchTrace с HttpAttempt и
RedirectHop. Он принимает тот же Budget для шагов 0–1 и SiteScope; `step=1` использует
оставшиеся 300 секунд/150 попыток, а не создаёт новый бюджет. Для шага 0 defaults -
60 секунд/15 попыток. Retry, redirect GET и fallback расходуют каждый по попытке;
отклонённое до транспорта DNS/назначение не расходует HTTP-квоту и остаётся наблюдением.
На один host начала запросов разделяются минимум одной секундой, независимо от origin.

HTTPX connect/read/write/pool timeouts - 5/15/10/5 секунд. Внешний asyncio.timeout по
монотонному Budget охватывает DNS, ожидание сериализации, pacing, backoff, TLS и весь поток.
Медленный поток с регулярными кусками также останавливается. Отмена вызывающим кодом
распространяется CancelledError, а не подменяется результатом успешной загрузки.

Чтение идёт через response.aiter_raw(), без автоматической распаковки HTTPX. LimitedBody
ограничивает encoded и decoded представления независимо (по 5 MiB). gzip/deflate распаковываются
инкрементально с max_length=остаток+1; не используется неограниченный decompress/flush.
Проверяется конец потока сжатия. При превышении лимита/ошибке тело incomplete, сохранённые
буферы не превышают лимит. Размер последнего полученного сетевого чанка может пересечь
encoded-порог; received_bytes отражает это, retained encoded_body ограничен. Ограничение
не означает побайтовый контроль чтения сетевых заголовков/TLS или объёма в ядре ОС.

Закрытие выполняется при success, read/protocol/TLS failure, отмене и лимите. Отдельно
закрывается TCP-поток, ещё не успевший завершить TLS handshake. Закрытие защищено от
обычной отмены через shield; сетевые данные после завершения GET не дочитываются.

## Границы результата и неоднозначности

- FetchTrace - транспортные данные в памяти, **не** опубликованный site.json.
  Нужна последующая интеграция с EvidenceStore и классификатором содержимого.
  Отсутствие trace.error означает отсутствие транспортного/политического сбоя;
  HTTP 403 остаётся отдельным status_code и не становится пригодным HTML.
- validate_site/CLI step0 пока сохраняют явный IMPLEMENTATION_NOT_AVAILABLE:
  финальная оркестрация, классификатор CAPTCHA/логина/JS/soft404 и публикация аудита ещё не готовы.
  Общий клиент доступен импортом, он не запускается автоматически.
- Неоднозначные пути с encoded `/`, `\\`, `?`, `#`, `%25`, controls и dot-segments
  отвергаются целиком. Они могут быть легальными для отдельного приложения, но в этой
  версии не переписываются и не запрашиваются. В query те же последовательности остаются
  непрозрачными данными: там не меняется граница назначения/пути.
- Literal `..` разрешается только как часть относительного Location по RFC; в явном входном
  URL/абсолютном Location он отвергается. Single-label host:port требует явного http://,
  чтобы не смешивать host с URI scheme. Числовой последний DNS label отвергается консервативно.
- Fallback после сбоя уже на другом разрешённом redirect-host не выполняется: новое
  соединение не подменяет исходный вход. Эта консервативная граница зафиксирована до полной оркестрации.
- Поддержаны identity/gzip/zlib-deflate. Brotli, zstd, цепочки Content-Encoding,
  raw-deflate и concatenated/trailing gzip явно отвергаются. Сжатые bytes не заменяются текстом.
- DNS getaddrinfo выполняется средствами ОС; после отмены может закончить фоновую DNS-операцию,
  но её результат уже не может открыть соединение. Из одного DNS-ответа выбран первый публичный IP;
  отказ другого адреса не скрывается автоматическим перебором.
- PSL - фиксированный снимок, не обещание знания будущих/всех многопользовательских зон.
  Его обновление требует явной ревизии и тестов. Для неизвестных зон автоматический www закрыт.
