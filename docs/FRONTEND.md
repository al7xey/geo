# Интерфейс и подключения моделей

Интерфейс на React и TypeScript сохраняет исходные стили itworx. Рабочий маршрут:
адрес сайта → редактирование вопросов → подтверждение → обработка → отчёт.
Из отчёта можно открыть расчёты, примеры ответов, план, выгрузки и общую ссылку.
Вход учебный: настоящих аккаунтов, хранения паролей и отправки писем нет.

## Запуск на Windows, macOS и Linux

Нужны Python 3.12+ и Node.js 24 для первоначальной сборки. Ubuntu и WSL не нужны.

```console
python run.py setup
python run.py ui-setup
python run.py ui
```

Откройте http://127.0.0.1:8767. Последняя команда запускает учебные ответы без API.
После сборки Node.js не нужен для работы сервера. Команды выполняются из корня
проекта; активировать виртуальное окружение вручную не требуется.

Для платного сбора заполните `.env` по образцу `.env.example` и запустите:

```console
python run.py ui --live
```

`.env` игнорируется Git. Ключи не возвращаются через HTTP и не включаются в сборку.
Подготовка вопросов запускается по кнопке на первом экране. Сбор ответов
запускается отдельно после проверки вопросов. Один проект — одна попытка сбора: до 20 вопросов, один ответ на вопрос и систему, до 800 выходных токенов.
При ошибке системы оставшиеся её вопросы пропускаются. Повторов, переключения
на другую модель и интернет-поиска при сборе ответов нет. Независимая проверка
разметки ограничена 20 запросами по 1600 выходных токенов; подготовка материалов
на шаге 10 — ещё одним запросом. Невыполненные задания остаются ожидающими.
Проверка четырёх уровней на четырёх системах составляет максимум 16 запросов.
Список систем определяется имеющимися ключами; Perplexity не включён.
Gemini использует Vertex Express для ключей `AQ.`, иначе Gemini Developer API.
Модели можно заменить через переменные `GEO_*_MODEL` в `.env`.

## Что действительно выполняется

В режиме `--live` программа не берёт готовые вопросы. Кнопка «Подготовить вопросы»
вызывает исходные шаги 0–2 через `tools/ui_prepare.py`: безопасная проверка адреса,
чтение до пяти страниц, профиль и до 40 вопросов. Используется исходный режим
`cheap`; отдельный платный интернет-поиск отключён. Для закрытого сайта можно
заранее ввести описание компании. Нужны ключ Claude и личный файл правил
`private/prompts/prompt_step2_profile_and_queries.md`. Правила и исходный код
шагов 0–4 не изменены. Сам шаг 2 может делать внутренние повторные попытки по
своим исходным правилам; ограничения «без повторов» ниже относятся к новым
подключениям сбора и перепроверки.

На шаге 3 интерфейс показывает созданные вопросы. По умолчанию выбираются
до пяти небрендовых вопросов каждого уровня, максимум 20. Можно изменить выбор
или оставить один вопрос каждого уровня. Сохранение вызывает исходные правила
`step3_review.check/save`, включая проверку длины, повторов и упоминаний бренда.
Полученные `profile.json` и `step4_input.json` с контрольной суммой становятся
входом сбора. До подтверждения вопросы к системам не отправляются.

Экономный веб-адаптер шага 4 получает по одному короткому ответу через API четырёх
систем и сохраняет исходный формат сбора. Это отдельный ограниченный режим:
оригинальный сборщик `tools/step4_collect.py` с поиском, адаптивными повторами и
своими моделями по-прежнему доступен через `run.py collect` без изменений.
Веб-режим не воспроизводит поиск и адаптивные повторы оригинального сборщика.

Шаг 5 выделяет упоминания. Шаг 6 делает осторожную первичную разметку правилами.
На шаге 7 OpenAI независимо проверяет неясные случаи и случайные 5% ответов,
видя исходный текст без первичной разметки. Это экономит отдельный модельный
проход по всем ответам. Сравнение идёт с правилами, а не с якобы выполненной
разметкой Haiku. Цитаты и их границы проверяет код. Подтверждённые расхождения
по случайной выборке не исправляют исходную разметку: выборка измеряет качество.
До 20 заданий выполняются за запуск; остальные явно остаются ожидающими.

Шаг 8 объединяет варианты названий. Шаг 9 считает проценты и принимает
проверенные технические данные шага 1. На шаге 10 при достаточных фактах сайта
Claude одним запросом готовит предложения; код проверяет страницы, цитаты,
числа и основания. Шаги 11–12 собирают план и отчёт. Все модельные выводы —
данные для проверки, а не команды программы. Ошибки API не подменяются
учебными ответами. Без контекста сайта материалы не выдумываются.

В режиме без `--live` остаётся учебный сценарий GoGetLinks. Можно также
импортировать готовые профиль, вопросы и ответы существующих шагов 0–4;
повторных запросов при импорте нет. Один ответ на вопрос пригоден для проверки
программы, но не для надёжных выводов об устойчивости моделей.

Всё сохранено под `private/app/<проект>/<запуск>/`: исходные вопросы и ответы,
`input/api-usage.json` с количеством запросов, ошибками и токенами, публикации
шагов 5–12 и `report/report_data.json`. Сырые ответы API остаются там же. Подготовка хранится в `preparation`,
подтверждение — в `review-*`, учёт перепроверки — в `model-jobs/usage.json`.
`api-attempt.json` в папке проекта предотвращает повторную платную попытку.
Не удаляйте этот файл для повторения теста.

Отчёт вычисляет показатели из реальных сохранённых ответов. Основная доля —
среднее по вопросам. Наблюдаемые факты, расчётные оценки, гипотезы и рекомендации
имеют разные основания и не смешиваются с уровнями вопросов A–D.

## Архитектура интерфейса

`frontend/src/app` — запуск, маршруты и стили; `pages` — страницы;
`widgets` — крупные блоки; `features` — действия пользователя;
`entities/audit` — договорённости о данных проверки; `shared` — HTTP, навигация
и общие элементы. Импорты направлены вниз по слоям через открытые `index`.
Исходный CSS сохранён; дополнительные правила находятся в `interaction.css`.
Шрифты поставляются локально. React не вставляет ответы модели как HTML.

Python-сервер `geo_audit.app_web` слушает только локальный адрес. Он хранит
подписанную метку учебного рабочего пространства в HttpOnly cookie, проверяет
Host, Origin и защитный токен изменения данных. Эта метка не является настоящей
регистрацией. Общую ссылку можно отозвать; она доступна только при работающем
локальном сервере. Выгрузки: HTML, JSON, CSV; PDF — через печать браузера.

Сборка `npm run build --prefix frontend` выполняет компиляцию TypeScript,
проверяет направления импортов и создаёт `frontend/dist`. Она не вызывает API.
