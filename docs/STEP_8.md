# Шаг 8: названия брендов и типы источников

Автономный offline-модуль Python. Принимает проверенную публикацию шага 7,
использует исходные бренды шага 6, источники шага 5 и допустимые уточнения шага 7.
Никаких SDK, ключей, HTTP, DNS, открытия страниц и имитации решений моделей.

```powershell
.\.venv\Scripts\python.exe -m geo_audit.step8 --step7-dir private/step7-review-v2 --output-dir private/step8-demo-001
.\.venv\Scripts\python.exe -m geo_audit.step8 --verify private/step8-demo-001
```

Выходная папка должна быть новой и находиться вне исходной публикации.
Для просмотра откройте report.html. Это статический HTML с экранированием,
CSP, без скриптов, внешних ресурсов и кликабельных ссылок на источники.
Наследуется происхождение ответов; synthetic не становится реальным измерением.

## Объединение названий

Автоматически нормализуются Unicode NFKC, регистр, пробелы и одна пара внешних
кавычек. Внутренние знаки сохраняются: Blue-Link и Blue Link — разные ключи.
Транслитерация и сходство SequenceMatcher >= 0.90 создают только предложения
на проверку. Порог сходства не является вероятностью совпадения компаний.
Rapidfuzz и другие новые зависимости не требуются.

Области идентичности разделены:

- target: подтверждённые в контексте первичных правил/проверки упоминания цели;
- non_target_candidate: обнаруженные имена других кандидатов; их существование
  и статус конкурента этим шагом не доказаны;
- unresolved: идентичность ещё ожидает шага 7.

Одинаковое написание в разных областях не объединяется. Контекстно раскрытый
алиас цели не делает все остальные упоминания того же сокращения целевыми.
Каноническая подпись цели берётся из профиля. Для других групп подпись выбирается
из наблюдавшихся первичных/проверенных имён по частоте, затем лексикографически.
Поле variants сохраняет дословные цитаты названий. Каталог не добавляет ненаблюдавшиеся
названия к variants. Синтетические примеры не служат справочником реальных компаний.

Каждый исходный бренд покрыт наблюдением. Если первичная каноническая подпись
скрывала несколько неразрешённых алиасов, они разделяются на отдельные буквальные
наблюдения; каждое такое наблюдение относится ровно к одной группе. answer_ids
уникальны: несколько упоминаний в ответе не превращаются в несколько ответов.
brand_occurrences.jsonl содержит answer_id, индекс первичного бренда, хеш первичной
разметки и текста, исходные цитаты/позиции, роль, ранг и происхождение уточнений.
Полное доказательство роли и контекста ранга сохраняется в input/annotations.jsonl.

Уточнения идентичности/ролей применяются только через проверенный слой шага 7,
к точному хешу первичной разметки и только вместо uncertain. Конфликты уверенных
решений остаются в исходном слое и quality.json. Если неизвестный алиас проверен
как чужой, используется reviewed_name, а не старая каноническая подпись цели.
Повторные задания для идентичности unresolved здесь не создаются.

## Источники

domain_types.json группирует уже наблюдавшиеся URL по точному hostname. Сохраняются
URL, уникальные ответы, отдельно пригодные ответы с цитированием и ссылкой в тексте.
Различаются hostname и регистрируемый домен: соседние поддомены автоматически не
получают один тип. URL не доказывает фактическое чтение страницы моделью.

Целевой домен и его поддомены получают first_party по профилю и company как тип
по декларации профиля, без проверки содержимого. fakel.test.evil.test не является
поддоменом fakel.test. Тип стороннего источника берётся только из явного локального
каталога; иначе unknown. Допустимые типы: review, media, directory, forum, company,
other, unknown. other означает явно выбранный иной тип, unknown — отсутствие данных.
Предположение по словам news/forum в имени сайта не считается классификацией.

## Явный справочник и будущие API

```powershell
.\.venv\Scripts\python.exe -m geo_audit.step8 --step7-dir private/step7-review-v2 --output-dir private/step8-catalog-001 --catalog private/entity-catalog.json
```

Формат: schemas/step8/EntityCatalog.schema.json. Учебный пример:
examples/contracts/step8/catalog.synthetic.json. Для alias_groups передаются aliases
и reason; для domain_labels — точный host, kind и reason. Пересекающиеся алиасы,
дубли доменов, пустые основания, неизвестные типы отклоняются. Каталог считается
явной декларацией оператора, а не результатом независимого аудита. Алиасы каталога
могут объединять только non_target_candidate; они не разрешают контекстную
неопределённость и не переводят чужие имена в target.

unresolved_entities.jsonl — ограниченная очередь compare_entity_names /
classify_source_host с executed=false, pending_api_key. executor.json фиксирует
отключённое выполнение. Импорт автоматического ответа модели и повторный запрос
при ошибке пока не реализованы: включение переменной с ключом ничего не запускает.
Подключение исполнителя потребует явного адаптера, строгой проверки схемы, исходных
ID/имён и доказательств перед созданием новой публикации. Без такого исполнителя
спорные названия остаются отдельными, а неподтверждённые типы — unknown.

## Скорость, ограничения и проверка

Нормализация выполняется один раз на публикацию, без циклов по провайдерам/API.
Сходство ищется только среди нецелевых групп с общими первыми двумя символами
транслитерации. У каждой группы для поиска берутся каноническое имя и до семи
первых нормализованных вариантов. Это ограниченный поиск кандидатов, не полный
поиск всех возможных алиасов; он может пропускать пары с разными префиксами.
До 10 000 сравнений пар, 100 заданий на пары и 100 заданий на домены по умолчанию.
Сначала в доменную очередь попадают наиболее часто цитируемые источники; остальные
помечаются deferred. Лимиты доступны через Step8Policy в Python. Достижение бюджета
не удаляет наблюдения и группы; незавершённость поиска отражается в summary/quality.

До 50 000 наблюдений, 10 000 групп; превышение прекращает сборку до записи результата.
Metadata-файлы до 4 MiB, входные JSONL и каждый выходной артефакт до 64 MiB,
входные снимки и вся публикация отдельно до 256 MiB. Сохраняются ограничения
предыдущих шагов на строки и фрагменты доказательств.

Сначала проверяется публикация шага 7, затем захваченные фиксированные файлы снова
сверяются с воспроизведёнными результатами. Manifest не задаёт произвольные пути
чтения. Используется общий confined I/O с запретом небезопасных ссылок. Публикация
пишется в новую папку; manifest.json — последний маркер завершённой записи.
--verify воспроизводит результат из собственных снимков, исходная папка шага 7
больше не нужна. Подмена выходного файла с обновлением его хеша также выявляется
пересчётом. Хеши обеспечивают согласованность, не криптографическую подлинность
всего внешнего набора данных.

Выход: brand_map.json, brand_occurrences.jsonl, domain_types.json,
unresolved_entities.jsonl, summary.json, quality.json, executor.json, validation.json,
report.html, input/ и последний manifest.json; общий storage создаёт пустой raw/.
status=partial при оставшейся идентичности, неизвестных типах, заданиях, ограничении
поиска или пустом корпусе. Это пригодный для следующего шага результат с ограничениями.

Четыре категории оснований аудита не меняются: наблюдения остаются фактами об ответах,
карта имеет явное основание нормализации. Причины отсутствия бренда, рекомендации
аудита и проценты видимости этот шаг не создаёт. Шаги 9–12 автоматически не запускаются.
