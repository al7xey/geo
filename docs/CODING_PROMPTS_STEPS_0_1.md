## Промпт 2. Сетевой клиент и шаг 0

```text
В C:\GEO продолжи реализацию после промпта 1. Прочитай AGENTS.md, docs/PROJECT_CONTEXT.md, docs/STEP_0_1_SPEC.md и текущий код. Реализуй общий ограниченный HTTP-клиент и полный шаг 0 по рабочей спецификации.

Нормализуй URL без потери пути/query, поддержи IDN, явные HTTP/HTTPS и HTTPS-first при отсутствующей схеме. При транспортной ошибке HTTPS разрешай отдельный HTTP fallback согласно конфигурации; сохраняй исходную ошибку и признак понижения схемы. Не используй verify=False. Ответы 401/403/404/429 и challenge не должны запускать обход через другую схему. Таймаут не означает, что у сайта нет HTTPS.

Используй ограниченный streaming GET, ручные редиректы, проверку каждого назначения, общий deadline, лимиты размера после распаковки, ограниченные временные повторы и Retry-After. Тестовый транспорт инъецируется отдельно, без production-выключателя безопасности.

Не расширяй crawl_scope автоматически на все поддомены. Внешний редирект страницы останавливается до запроса и возвращает needs_input; дополнительный хост задаётся через --allow-host. Храни полную историю. HTML-оболочка JS не является автоматическим провалом, а код 200 не является гарантией полезной страницы. Реализуй site.json и переиспользуемое доказательство первого ответа.

Добавь содержательные офлайн-тесты: HTTPS успех; явный HTTP с редиректом на HTTPS; HTTPS transport failure и рабочий HTTP; неверный сертификат без отключения проверки; HTTP обратно на неисправный HTTPS; 403 без fallback; IDN и сохранение /ru/; внешний редирект без запроса назначения; цикл; localhost/private IPv4/IPv6 и смена назначения DNS; 200 challenge; бинарный/слишком большой ответ. Для тестов не обращайся к внешним сайтам. Запусти соответствующие проверки и сообщи результаты и реальные ограничения.
```
