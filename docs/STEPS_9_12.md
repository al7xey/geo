# Шаги 9–12: расчёты и итоговый отчёт

Продолжение принимает сохранённый результат шагов 5–8. Новых зависимостей нет.
Расчёты, план и отчёт работают локально, без ключей и вызовов моделей.
Исходные шаги 0–4 не меняются. Ветка реализации: `feature/steps-9-12`.

## Запуск

На Windows из папки проекта:

```powershell
python run.py setup
python run.py demo --through12
```

На macOS/Linux используйте `python3`. Учебный запуск обрабатывает 480 вымышленных
ответов. Итоговый файл — `private/demo/ДАТА-ВРЕМЯ/final/report.html`;
точный путь выводится в терминал. Браузер и платные API не запускаются.

Для своих уже собранных ответов сначала выполните обычный `analyze`, затем:

```powershell
python run.py finish --chain-dir private/complete/PROJECT --output-dir private/final/PROJECT
```

Если есть только отдельная публикация шага 8:

```powershell
python run.py finish --step8-dir private/step8/PROJECT --output-dir private/final/PROJECT
```

Добавьте `--site-dir private/runs/STEP1_PUBLICATION`, чтобы включить проверенные
страницы, цитаты и технические проверки. Без них отчёт объяснит отсутствие данных,
а подготовка текста останется в ожидании контекста. Передавать один произвольный
`checks.json` вместо проверенной публикации нельзя.

Папка результата должна быть новой, отдельно от входов. Источники не переписываются.
`chain.json` записывается последним. Для проверки сохранённого результата:

```powershell
python run.py finish --verify private/final/PROJECT
```

Проверка воспроизводит этапы и связывает фактические входы каждого этапа с выходами
предыдущего. Контрольные суммы проверяют согласованность, а не подлинность API.

## Шаг 9. Подсчёт

**Вход:** проверенная публикация шага 8; необязательно — сохранённый технический обход.

**Действия:** расчёт явного совпадения названия, подтверждённого присутствия,
рекомендации, отрицательной рекомендации и ссылки на сайт. Отдельно сохраняются
показатели по системам, моделям, настройкам и уровням A–D.

Сначала считается доля для каждого вопроса и состава «система, модель, настройки».
При объединении систем их доступные доли внутри вопроса имеют одинаковый вес.
Затем усредняются вопросы. Дополнительные повторы не увеличивают вес вопроса.
Ошибки сбора, исключённые системы и брендовые вопросы не возвращаются в измерение.

Неясная идентичность не засчитывается в подтверждённое присутствие, но остаётся
в его знаменателе и отдельном счётчике. Неясные смысловые роли исключаются
из знаменателя рекомендаций. Поэтому рядом с долей показываются покрытие,
неопределённость и ограничения надёжности. Отсутствие данных — `null`, а не ноль.

Разброс оценивается повторной выборкой вопросов с возвращением. По умолчанию
400 повторных выборок; начальное значение генератора фиксировано. Это описательный
разброс выбранных вопросов, а не доказательство свойств всех будущих ответов.
Для одного вопроса интервал не строится. Пригодные повторы разделяются на
«всегда», «иногда», «никогда» и «неясно»; пустой набор не считается «никогда».

Частоты других названий и источников считаются по уникальным пригодным ответам.
Они явно отличаются от основного среднего по вопросам. Другие названия остаются
кандидатами: их существование и полнота извлечения не доказаны.

**Выход:** `aggregates.json`, `answer_metrics.jsonl`, `cohorts.json`, `context.json`,
`source_page_jobs.jsonl`, `validation.json`, входные снимки и `manifest.json`.
Все числовые значения отчёта имеют записи в реестре `aggregates.numbers`.

### Необязательная проверка внешних страниц

По умолчанию сайты не открываются. Для ответов уровней C и D выбирается не более
пяти наиболее часто цитируемых внешних URL. Повторы одного URL не создают
несколько посещений. Явный отдельный запуск:

```powershell
python run.py sources --step9-dir private/final/PROJECT/step9 --output-dir private/sources/PROJECT --allow-network
python run.py sources --verify private/sources/PROJECT
```

Эта команда обращается к сайтам, но не к моделям. Она использует существующий
безопасный обходчик: публичный числовой IP, проверка адреса соединения, имени
и сертификата, robots и общий бюджет внутри каждого посещения. Для страницы
выбирается не более одной страницы обхода, карты сайта и браузер отключены.
Предел — пять страниц, до шести попыток и двенадцати секунд на посещение.
При ошибке неизвестность не превращается в отсутствие компании.

Проверяется только буквальное название в сохранённом фрагменте до 20 000 символов.
Также ищутся до тридцати частых других названий. Совпадение не доказывает
идентичность или рекомендацию, а ссылка в ответе — чтение страницы моделью.
Исходные публикации и цитаты сохраняются для повторной проверки.

Чтобы включить наблюдения в новый итоговый отчёт:

```powershell
python run.py finish --chain-dir private/complete/PROJECT --source-checks-dir private/sources/PROJECT --output-dir private/final/PROJECT-with-sources
```

Выбор страниц и варианты названий должны совпадать с текущим аудитом.
Данные внешней проверки включаются как отдельные наблюдения; сам расчёт сети не требует.

## Шаг 10. Темы и подготовка содержания

**Вход:** расчёты и подтверждённые цитаты страниц из шага 9.

Отбираются вопросы, где нет явного совпадения названия, подтверждённого упоминания
и неясной идентичности, а другой кандидат рекомендован минимум в 30 % пригодных ответов.
Без пригодных ответов тема не отбирается. Неясность нельзя назвать доказанным пробелом.

Вопросы предварительно группируются по словам, максимум в шесть тем. Если вопрос
один, создаётся одна тема, без искусственного дублирования. Существующие страницы
подбираются как кандидаты; совпадение слов не доказывает наличие или отсутствие ответа.

При наличии тем создаётся одно задание будущей модели. Его данные ограничены
24 000 символами, ответ — 1600 токенами. Включаются только выбранные вопросы,
краткие сведения о компании, страницы и подтверждённые цитаты. Личные заметки,
полные ответы моделей и исходные API-конверты не передаются. При нехватке контекста
задание получает `needs_site_context`; иначе — `pending_api_key`. Исполнитель отключён.
Предусмотрены одна начальная попытка, один повтор и сохранение плана без текста при неудаче.

Можно заранее принять внешний результат без подключения API:

```powershell
python run.py finish --chain-dir private/complete/PROJECT --site-dir private/runs/STEP1_PUBLICATION --gap-results private/gap-response.json --output-dir private/final/PROJECT-with-drafts
```

Формат — `schemas/step10/GapResponse.schema.json`. Нужны точные `job_id` и
`context_sha256` из задания той же публикации. Учебный пример с неназначенным
идентификатором не подходит к настоящему заданию без адаптации.

Проверяется принадлежность темы, страницы, дословность цитаты, число пунктов новой
страницы, ссылки на факты и отсутствие новых чисел или цен вне подтверждённых фактов.
Неверные элементы отклоняются, правильные остаются. Структурная ошибка сохраняет
темы без готового материала. Учебный материал не изменяет настоящий аудит.

Проверка цитат и чисел не доказывает смысловую правильность любого пересказа.
Даже принятый текст остаётся заготовкой для проверки человеком, не публикуется автоматически.

**Выход:** `gaps.json`, `gap_jobs.jsonl`, `review_intake.jsonl`, `executor.json`,
проверки и снимки. Если тем нет, модельное задание не создаётся.

## Шаг 11. Находки и план

**Вход:** расчёты, технические проверки и темы шага 10.

Правила выбирают до четырёх главных наблюдений. Каждое действие ссылается
на конкретный показатель, вопрос, техническую проверку, тему или источник.
Действие без основания не создаётся. План разделён на «Неделя 1», «Недели 2–4»
и «Дальше»; внутри периода сначала идут действия по большему числу вопросов.
Для каждого действия указаны основание, заготовка при наличии и способ проверки.

Наблюдаемые факты, расчётные оценки и рекомендации сохраняются раздельно
в `categories/`. Неподтверждённые причины не выдаются за гипотезы с доказательствами:
файл гипотез пуст и имеет пояснение. План не обещает рост упоминаний, трафика или продаж.

**Выход:** `findings.json`, `plan.json`, четыре категории оснований и проверка ссылок.
Модели не нужны.

## Шаг 12. Итоговый отчёт

**Вход:** проверенная публикация шага 11 и связанные данные предыдущих этапов.

Создаётся самостоятельный HTML с показателями, разбивкой по системам и вопросам,
устойчивостью, техническими наблюдениями, названиями, источниками и планом.
Учебные данные выделены заметно. У пустых разделов указана причина отсутствия данных.
Все выводимые числовые показатели сверяются с реестром шага 9.
Служебные задания и внутренние инструкции в HTML не включаются;
фрагменты со служебными метками скрываются с пояснением.
Пользовательский текст экранируется; скриптов и внешних ресурсов нет.

**Выход:** `report.html`, `report_data.json`, `validation.json` и файлы расчётов,
находок, тем и плана. `report_data.json` предназначен для последующего интерфейса.
Это готовый локальный отчёт, а не реализация React-интерфейса из отдельного задания.
PDF можно сохранить печатью из браузера; автоматически браузер не запускается.

## Файлы и отдельные команды

```text
FINAL/
  step9/               расчёты и исходные снимки шага 8
  step10/              темы, задания и принятие заготовок
  step11/              находки и план с основаниями
  step12/              отчёт и проверка его чисел
  report.html          итоговый просмотр
  aggregates.json      расчёты
  findings.json        находки
  plan.json            план
  report_data.json     данные для интерфейса
  chain.json           последний признак завершённой записи
```

Отдельные этапы доступны через `python -m geo_audit.step9` … `step12` с параметрами
`--stepN-dir`, `--output-dir` и отдельным режимом `--verify`.
Схемы проверяются командой `python tools/generate_tail_schemas.py --check`
из установленного окружения проекта.

Добавление ключа не выполняет задания автоматически. Подключение API должно
добавить явный исполнитель с лимитами расходов и проверкой ответа по готовой схеме.
Расчёты, план и отчёт при этом переписывать не требуется.
