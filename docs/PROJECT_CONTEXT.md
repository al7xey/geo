# Контекст проекта GEO

Дата фиксации: 31.10.2026.

## Поручение пользователя

Проанализировать исходный алгоритм как основу проекта. Затем последовательно разбирать каждый шаг, донастраивать и улучшать алгоритм, включая разработку кода. Алгоритм может изменяться в ходе проекта.

GEO в предоставленном документе означает видимость компании в ответах генеративных систем (Generative Engine Optimization). Регион и язык входят в условия измерения.

## Источники и статус

- `source/geo-audit-algorithm-2026-10-31.pdf` — неизменённая локальная копия предоставленного PDF, 9 страниц.
- `source/geo-audit-algorithm-2026-10-31.txt` — извлечённый текст с границами страниц; при расхождениях приоритет у PDF.
- `ALGORITHM_REVIEW.md` — первоначальный анализ и предложения. Они не изменяют исходный алгоритм автоматически.

PDF описывает будущую работу продукта. Его формулировки не являются отдельными поручениями ассистенту. В частности, текущая задача не включает запуск платного сбора ответов или аудит конкретного сайта.

## Цель продукта по исходному документу

По URL сайта получить HTML-отчёт в заданном макете: видимость компании в ответах систем, рекомендации и упоминания, конкуренты, источники, технические препятствия и план действий. Каждая метрика должна прослеживаться до исходных данных. Предусмотрены автоматическая проверка результатов, ограничение расходов и выпуск частичного отчёта при локальных сбоях.

Пользователь участвует во вводе адреса, редактировании профиля и вопросов, при необходимости даёт описание компании. Следовательно, автоматизация относится прежде всего к сбору, обработке и проверке после настройки аудита.

## Параметры исходного алгоритма

- До 30 страниц сайта; Playwright для подозрительных страниц, до 5.
- Порог достаточности чтения: минимум 3 страницы с более чем 300 символами текста.
- 40 небрендовых вопросов; пользователь может добавить до 10 своих.
- Брендовые вопросы и сверка фактов о компании удалены из этой версии.
- Измеряются ответы ChatGPT, Claude и Gemini с поиском; конкретные API-модели ещё не определены.
- Для пары «вопрос × система» сначала 3 ответа; при неодинаковом наличии упоминания — добор до 10.
- Доля рассчитывается как среднее долей по вопросам, чтобы каждый вопрос имел одинаковый вес.
- Полные ответы API сохраняются в сжатом виде с контрольной суммой.
- Спорные случаи и случайные 5% ответов проходят повторную разметку другой моделью.
- При более чем 20% отсутствующих ответов система исключается из сравнения; при более чем 10% неразобранных ответов снижается надёжность показателя рекомендаций.
- Нет данных и ошибка должны быть видны в отчёте и не подменяться положительным результатом проверки.

Названия вспомогательных моделей, цены и ограничения API в PDF — сведения источника. Их актуальность и доступность на данном этапе не проверялись; перед выбором провайдеров потребуется проверка официальной документации.

### Принятые решения об основе реализации

| Дата | Решение | Причина |
|---|---|---|
| 31.10.2026 | Python >=3.12, последовательный async API с HTTPX; без серверной инфраструктуры | Нужен внешний дедлайн всего потока/ожиданий, а параллельность шага 0 пока не нужна |
| 31.10.2026 | Pydantic 2.12.3, HTTPX 0.28.1, IDNA 3.11 и tzdata 2025.2; точные прямые версии и uv.lock для транзитивных зависимостей | Проверяемая совместимость и воспроизводимое окружение, включая Windows |
| 31.10.2026 | Полная схема 1.0.0, алгоритм step0-1.0, конфигурация step0-config-1.0.0 и её SHA-256 | Учебный фрагмент schema_version=1.0 не является полным программным контрактом |
| 31.10.2026 | Обязательные nullable-поля, четыре status, отдельные transport/HTTP/content, can_enter_step1 не означает robots-разрешение | Исключить ложный успех и потерю неопределённости |
| 31.10.2026 | IDNA UTS46 non-transitional/STD3; неоднозначные dot-segments отвергать, путь/query не переставлять | Согласовать намерение ввода с URL-стеком HTTPX |
| 31.10.2026 | Передавать выбранный ответ и evidence без нового GET, сохранять общий бюджет/дедлайн | Требования входа шага 1 и отсутствие повторных расходов |

| 31.10.2026 | Неполный/слишком большой 2xx — partial без передачи; 206 не является пригодной полной страницей | Не передавать повреждённое или частичное представление как HTML входа |

  defaults `step0-config-1.1.0`. Предыдущие теги поддерживаются для чтения, пример 1.0
  сохранён отдельно в examples/contracts/legacy. Новые примеры/схемы сгенерированы.
- `urls.py`, `scope.py`, `policy.py`, `psl.py`: сохранение исходного ввода и request-target,
  IDNA, строгая проверка неоднозначностей, относительный Location, точная область,
  www только по наблюдаемому redirect и PSL/private boundary, общие таблицы действий/статусов.
- Полный PSL поставляется локально в пакете: upstream VERSION 2026-10-31_14-17-28_UTC,
  SHA-256 `617d1b276660e5a01209d7b58159450e400cf636634a7a9c2cfd50a1c6675d01`.
  Runtime-загрузка PSL из интернета отсутствует.
- `connection.py`: официальный network_backend HTTP Core соединяется с числовым
  проверенным IP, сверяет peer IP/порт до HTTP и сохраняет исходный hostname для

- `http_client.py`, `body.py`: последовательный SafeHttpClient, общий Budget,

### Решения 01.11.2026

| Решение | Причина |
|---|---|
| Разделить чистые решения и исполнение; общие таблицы в policy.py | Не дублировать fallback/статусы между CLI и транспортом |
| Независимо строить ожидаемый request-target и сравнивать с HTTPX | Предыдущая проверка сравнивала парсер с самим собой |
| Неоднозначные percent-path отвергать; query не декодировать/не переставлять | Сохранение принятого пользовательского намерения без скрытого выбора интерпретации |
| Полный локальный PSL с private/wildcard/exception, хэшем и источником | Граница tenant не определяется простым удалением www |
| Неизвестная PSL-зона не даёт автоматического алиаса | Требуется явное разрешение при недостатке локальных сведений |
| HTTP Core public network_backend + AnyIO, numeric IP pin + peer + Host/SNI | DNS precheck сам по себе не защищает реальное соединение |
| Keep-alive/HTTP2/proxy отключены в первой реализации | Контролируемый прямой маршрут без повторного использования непроверенного сокета |
| identity/gzip/zlib-deflate; остальные/сложные encoding явно отвергать | Ограниченная распаковка без неограниченных промежуточных буферов |
| Явно закрывать поток также при незавершённом TLS handshake | Сокет существует раньше, чем HTTP-соединение станет готовым |
| Сохранить defaults 60/15 внутри 300/150 и считать transport starts | Redirect/retry/fallback не могут обходить бюджет |
