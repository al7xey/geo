# Контекст проекта GEO

Актуализировано 01.11.2026 по коду пакета 0.3.1 и приёмке редакции 0.3.x.

## Цель и источники

GEO — Generative Engine Optimization: анализ видимости компаний в ответах генеративных
систем. Пользователь поручил последовательно разбирать и улучшать алгоритм, включая код.
Текущая область: только шаг 0 и контракт входа шага 1. Robots, обход шага 1, вопросы,
браузер и платные API не реализуются и не запускались.

- docs/source/geo-audit-algorithm-2026-10-31.pdf — исходный пользовательский PDF, сохранён.
  Сопутствующий .txt — извлечённый текст; при расхождении приоритет у PDF.
- steps/STEP_0_ALGORITHM_v1.md и steps/STEP_1_ALGORITHM_v1.md — подробная рабочая редакция
  1.0 от 31.10.2026; соответствующие PDF в output/pdf сохранены. Для реализации этапов
  использовать эти документы и датированные принятые уточнения ниже.
- PROMPTS_STEP_0.md и output/pdf/Промты для Шага 0.pdf — восемь промптов разработки,
  исходные тексты сохранены. Наличие документа не означает выполнения его требований.
- ALGORITHM_REVIEW.md — первоначальный анализ и предложения. Предложения по метрикам,
  адаптивным повторам, поставщикам моделей, сущностям и шагам 2–12 ещё не приняты.
- STEP_0_1_SPEC.md и CODING_PROMPTS_STEPS_0_1.md — более ранние проектные черновики,
  не источник актуального состояния кода.

PDF описывают систему, сами по себе не поручают запускать аудит или платные API.
Учебный JSON schema_version=1.0 не заменяет полный программный контракт.

## Фактическое состояние

Репозиторий C:\GEO, Python >=3.12, пакет geo-audit 0.3.1. Реализованы:

- Нормализация без сети, точный scope, локальный полный PSL с private/wildcard/exception.
  Снимок VERSION 2026-10-31_14-17-28_UTC, SHA-256
  617d1b276660e5a01209d7b58159450e400cf636634a7a9c2cfd50a1c6675d01.
- Последовательный async SafeHttpClient: numeric-IP pin и peer перед HTTP, исходные Host/SNI,
  TLS verification, ручные redirects/retries/fallback, Retry-After/pacing, encoded/decoded caps,
  общий deadline. Proxy/env trust/cookies/keepalive/HTTP2 отключены; DNS не кэшируется.
- validate_site с инъекцией config/client/Budget/TimeServices/store; полноценный CLI.
  HTML/JS/barrier/placeholder/empty/binary/incomplete оцениваются с основаниями/confidence.
- Новая приватная папка на run; raw тела и attempt observations, raw/manifest.json,
  journal/config/budget и финальный site.json. Atomic publish, SHA-256, handle-based no-follow
  защита. Отмена сохраняет завершённые наблюдения; программные ошибки не маскируются сетью.
- Step1Input и Step1Handoff: передача готового FetchResult с тем же Budget либо загрузка
  из сохранённой папки с проверкой версий/хронологии/scope/файлов/hash/representations/свежести.
  Loader не обращается к сети, не начинает обход; crawl_permission=unknown.

Полные схемы: schemas/; синтетические примеры: examples/contracts/; генератор выпускает
32 воспроизводимых артефакта. Примеры с фиксированным временем не являются действующим входом.
Сохранён архивный пример 1.0. Полноценная текущая схема 1.2.0, algorithm step0-1.2,
config step0-config-1.2.0 и config_sha256. Смешанные/неизвестные версии отвергаются.
Пакет 0.3.0 завершает ранее закоммиченную, но не принятую оркестрацию 0fa9d78.

## Проверенное поведение и отчёты

Полная приёмка оформляется по всем составным требованиям, а не проценту покрытия:

- implementation/STEP_0_REQUIREMENTS.md — актуальная матрица восьми промптов, компонентов,
  воспроизводящих тестов, статусов и ограничений.
- implementation/STEP_0_ARCHITECTURE.md — актуальные API/состояния/публикация/дедлайн.
- implementation/STEP_0_VALIDATION.md — исходное состояние, финальные проверки, PDF hashes.
- implementation/STEP_0_SECURITY_REVIEW.md — независимая модель угроз, подтверждённые
  дефекты и исправления, scanner versions/results, ограничения.
- implementation/STEP_0_PERFORMANCE.md — методика и агрегаты сравнения пяти сценариев.
  Benchmark-инструмент сохранён; сырые samples оставлены локально и исключены из Git
  последующим требованием пользователя о чистоте репозитория.
- implementation/STEP_0_NETWORK_AND_POLICY.md и STEP_0_NETWORK_VALIDATION.md — исторический
  сетевой этап 0.2.0; его формулировки о незавершённом runner более не актуальны.

Фактически выполнен полный suite: 339 passed, 1 skipped после completion-аудита 0.3.1.
Реальный TCP/TLS IPv4/IPv6, wrong hostname/untrusted CA/peer mismatch/handshake timeout
проверены отдельно от mocks. Сквозная интеграция: реальный runner на контролируемом
HTTPS-сайте → файлы → новый процесс consumer без разрешённых socket/DNS операций.
Success/partial/denied/corrupt/unknown version/expired проверены; GET остался один.
Файловый symlink тест skipped из-за WinError 1314; hardlink/junction/directory rename race
проверены реально. POSIX integration и живой внешний сайт не проверялись.

Mypy strict, Ruff, Bandit, lock/pip check, генерация контрактов и wheel smoke выполняются
по командам README. pip-audit после исправления pytest: 56 зависимостей, 0 известных
уязвимостей, 0 skip. Отсутствие scanner findings не означает полной безопасности.

Дополнительная приёмка чистоты: 101 необходимый файл, включая workflow; полная инвентаризация в
STEP_0_VALIDATION.md. .gitignore расширен, два сырых benchmark JSON сняты с учёта и
оставлены локально. Все tools включены в Ruff/compileall/Bandit. Явный sdist include
уменьшил его с 102 до 33 файлов; wheel содержит 31 файл. В отдельной копии только из
версионируемых исходников установка uv --no-cache sync --locked и полный suite повторены:
339 passed, 1 skipped (0.3.1). Новый audit cache: 56 зависимостей/0 vulnerabilities. Архивы
рабочей и чистой копии побайтово одинаковы; handoff проверен также из установленного wheel.

## Ограничения и следующий этап

Только прямой маршрут; первый проверенный IP без перебора; ограниченные тела в памяти;
эвристики без исполнения JS; SHA-256 без подписи каталога; доверенные UTC часы. POSIX,
file symlink без Windows privilege, аппаратный crash/power loss и live public smoke не приняты
как проверенные. Исходные PDF и полезные инструменты подготовки документов сохранены.

Следующая отдельная задача — шаг 1 по его подробному алгоритму: robots/очередь/ограниченный
обход/checks/material. Наличие Step1Input не означает, что этот обход реализован или разрешён.
Предложения обзора по шагам 2–12 остаются предложениями.
