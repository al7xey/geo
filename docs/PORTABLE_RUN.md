# Запуск на Windows, macOS и Linux

Программа запускается обычным Python. Ubuntu, WSL и Docker не нужны.
Требуется Python 3.12 или новее и интернет для первоначальной установки.
На macOS/Linux команда обычно называется `python3`, на Windows — `python` или `py -3.12`.
Команды ниже выполняются из папки проекта. Активация окружения не требуется.

## Установка

```text
python run.py setup
```

На macOS замените `python` на `python3`. Установщик создаёт отдельное окружение
`.bootstrap` для закреплённого uv 0.9.7 и окружение `.venv` для программы.
Зависимости берутся из `uv.lock`; системные пакеты Python не изменяются.
По возможности используется уже установленный Python 3.12; uv может загрузить
подходящий Python. Права администратора не нужны.
Учебные данные и результаты не отправляются в сеть.

## Учебный запуск без API

```text
python run.py demo
```

Обрабатываются 480 вымышленных ответов из `examples/mock_answers_v1/input`.
Скрипт создаёт учебный вариант файлов сбора и выполняет шаги 5–8, затем проверяет
целостность результатов. Данные помечены учебными. Ответы со статусами вроде
`truncated` при преобразовании считаются ошибками сбора, а не успешными ответами.
Исходный набор не изменяется. Такой прогон проверяет соединение частей программы;
он не заменяет прямые тесты исходного набора с его подробными статусами.

Путь к `report.html` выводится в терминал. Браузер автоматически не запускается.
Отчёт содержит ссылки на результаты каждого шага. Нейросеть повторную проверку
не выполняет: задания остаются в ожидании. Итоговые проценты относятся к шагу 9.

## Свои сохранённые ответы

```text
python run.py analyze --step4-input private/approved/step4_input.json --answers-dir private/answers --output-dir private/result-001
python run.py verify private/result-001
```

Рядом с `step4_input.json` нужен согласованный `profile.json`; другой путь можно
задать параметром `--profile`. В папке ответов нужен `answers.jsonl` исходного сборщика.
Папка результата должна быть новой и находиться отдельно от входных файлов.
Для вымышленных данных добавьте `--synthetic`. Проверка результата работает без сети.

## Остальные команды

- `python run.py --help` — список команд.
- `python run.py prepare --help` — параметры исходных шагов 0–2.
- `python run.py review --help` — проверка вопросов шага 3.
- `python run.py collect --help` — сбор шага 4 с продолжением до шага 8.
- `python run.py serve --help` — параметры локального технического интерфейса.
- `python run.py audit --help` — параметры технической проверки сайта.

Команды `prepare`, `collect`, `audit` при обычном выполнении могут обращаться в сеть.
Платные шаги требуют ключей и явно заданных ограничений исходного сборщика.
Наличие ключа не запускает их автоматически. Учебный запуск ключей не читает.
Исходный код шагов 0–4 сохранён без изменений.

## Проверки на разных системах

GitHub запускает проверки на Windows, macOS и Linux. Это три независимые среды
проверки; устанавливать Linux для работы на Windows или macOS не нужно.
На Windows тест остановки TLS-подключения по сроку использует SelectorEventLoop.
Остальные тесты сохраняют стандартный цикл, в том числе поддержку дочерних процессов.
Реальные проверки TLS, имени сервера и адреса соединения остаются. Это настройка тестов,
а не изменение сетевых правил программы. Подробные имена тестов и снимок стека
через 60 секунд помогают найти зависание, если оно повторится.
В одном тесте macOS учтён сброс соединения при закрытии учебного TLS-сервера:
обрабатывается только ошибка уже закрываемого серверного соединения.
Проверки запросов и соединения со стороны программы не меняются.
