# 3. Защищённый сетевой слой

Продолжи разработку в C:\GEO по актуальному алгоритму шага 0.

Реализуй общий HTTP-клиент, пригодный для повторного использования шагом 1.

Обязательные свойства:

- TLS verification;
- ручная обработка редиректов;
- проверка назначения до каждого соединения;
- явная политика прокси, cookies и переменных окружения;
- ограниченные повторы;
- Retry-After;
- сетевые таймауты и отдельный общий deadline;

- закрытие соединений при ошибке, отмене и превышении лимита.

Соблюдай начальные пределы алгоритма: 60 секунд и 15 HTTP-попыток для шага 0 внутри общего бюджета шагов 0–1. Redirect и retry расходуют попытки. Исключи скрытые повторы HTTP-транспорта.

Защита назначения должна учитывать:
- IPv4 и IPv6;
- private, loopback, link-local, reserved и metadata-адреса;

- DNS-ответы и смену адреса;
- каждый редирект;
- повторное использование соединения;
- выбранный proxy-маршрут.

Один DNS precheck не считать защитой от DNS rebinding. Свяжи проверенное назначение с фактическим соединением через корректный transport/egress-механизм. Сохрани проверку hostname сертификата и SNI при подключении к проверенному адресу.

Добавь офлайн-тесты транспорта и отдельные контролируемые интеграционные проверки границ соединения. MockTransport сам по себе не доказывает защиту реального подключения.

2. Загрузка из каталога запуска через site.json и raw-манифест.

Загрузчик проверяет версии, согласованность полей, наличие файлов, хэши и допустимость путей внутри каталога запуска. При повреждении возвращает INPUT_ARTIFACT_INVALID. Не подставляй пустой HTML вместо отсутствующего доказательства.

can_enter_step1 не является разрешением robots. Загрузчик сам не начинает обход.

Добавь интеграционную проверку: шаг 0 сохраняет результат, затем потребитель шага 1 загружает его и получает тот же HTML и ограничения без сетевого запроса. Проверь ok, допустимый partial, needs_input, failed, повреждённый файл, неизвестную версию и истёкший бюджет. Сам обход шага 1 пока не реализуй.
